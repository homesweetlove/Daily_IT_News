## IT 이슈

### 1. Meta Muse 영국 제공…서비스 연결 권한과 데이터 설정이 관찰 지점

**핵심 요약:** Meta의 24일 영국 출시 안내에 따르면 개인 AI 에이전트 **Muse**는 영국의 **18세 이상** 이용자에게 iOS·Android·웹·WhatsApp으로 제공된다. 무료 이용과 추가 사용량을 위한 선택형 구독을 제공하며, 연결 앱과 웹사이트를 통해 작업을 수행하도록 설계됐다. 이번 발표의 대상 지역은 영국이다. [Meta 공식 출시 안내](https://about.fb.com/news/2026/11/introducing-muse-in-the-uk-a-personal-ai-agent-you-control)

**왜 중요한가:** Meta는 구매 때마다 이용자 승인을 받으며, 다른 작업의 허용 범위·기간과 연결 서비스를 이용자가 관리할 수 있다고 설명했다. 다만 같은 Accounts Center에 있는 Facebook·Instagram·Threads 계정은 자동 연결된다는 안내도 있다. 사용자가 확인해야 할 범위는 새로 연결한 외부 서비스뿐 아니라 기존 Meta 계정 연결까지 포함한다. [Meta의 권한·연결 설명](https://about.fb.com/news/2026/11/muse-now-available-in-the-uk-muse-does-the-work-you-stay-in-control)

**관찰 포인트:** Meta는 Muse 대화·보관 정보를 광고 시스템과 공유하지 않는다고 설명한다. 별도로 AI 개발·개선에 상호작용을 사용하는 설정은 시작 시 켜져 있으며 Data controls에서 끌 수 있다고 안내한다. **편집부 제안:** 연결 앱, 승인 범위, 기억과 AI 개선용 데이터 설정을 각각 확인하자. 이는 업체가 밝힌 정책·설정에 대한 설명이며 독립적인 보안 검증 결과를 뜻하지 않는다. [공식 데이터 처리·설정 안내](https://about.fb.com/news/2026/11/muse-now-available-in-the-uk-muse-does-the-work-you-stay-in-control)

### 2. RDS for SQL Server, 인스턴스당 데이터베이스 상한 500개로 확대

**핵심 요약:** AWS는 11월 24일 RDS for SQL Server의 인스턴스당 데이터베이스 상한을 기존 **100개에서 최대 500개**로 확대했다고 발표했다. 대상은 **4 vCPU 이상, xlarge 이상**의 비버스터블 인스턴스이며 RDS가 지원하는 SQL Server 버전에 적용된다. [AWS 공식 발표](https://aws.amazon.com/about-aws/whats-new/2026/11/rds-sqlserver-supports-500-databases-per-instance)

**왜 중요한가:** 여러 데이터베이스를 운영하는 SaaS·멀티테넌트 환경에서 인스턴스 배치를 다시 검토할 수 있는 변화다. Single-AZ에서는 Enterprise·Enterprise Developer·Standard·Standard Developer·Web 에디션을 지원한다. Multi-AZ에서는 Enterprise·Enterprise Developer의 Always On Availability Groups 구성과 Web 에디션이 대상이다. **Database Mirroring 기반 Multi-AZ, Standard Edition Multi-AZ와 더 작은 인스턴스는 기존 제한을 유지**한다. [에디션·고가용성 조건](https://aws.amazon.com/about-aws/whats-new/2026/11/rds-sqlserver-supports-500-databases-per-instance)

**관찰 포인트 — 편집부 제안:** 상한 확대를 계기로 통합을 검토한다면 실제 CPU·메모리·I/O, 유지보수와 장애 영향 범위를 함께 비교하자. 데이터베이스 개수 상한이 늘었다는 사실만으로 기존 인스턴스의 처리 용량까지 늘어나는 것은 아니므로 대표 부하로 검증하는 편이 좋다. [발표된 적용 범위](https://aws.amazon.com/about-aws/whats-new/2026/11/rds-sqlserver-supports-500-databases-per-instance)

## 보안 이슈

### 1. Hex 서비스 침해 공지…비밀번호 변경·2FA 재설정 권고

**핵심 요약:** Erlang·Elixir 패키지 생태계의 Hex 운영자는 **11월 23일 웹 서버에서 명령 실행이 발생**했다고 밝혔다. 해당 취약점 **CVE-2026-129514**는 24일 공개됐다. CNA 공식 기록은 비인증 요청의 역직렬화가 BEAM 프로세스 사용자 권한의 운영체제 명령 실행으로 이어질 수 있으며 실제 서비스에서 악용됐다고 명시한다. [운영자 사건 공지](https://hex.pm/blog/security-incident-on-hexpm) · [CNA 공식 CVE 기록](https://cna.erlef.org/cves/CVE-2026-129514.html)

**왜 중요한가:** 운영자는 패키지 무단 변경·데이터베이스 변경·지속 접근 증거를 찾지 못했다고 설명했다. 그러나 데이터베이스 읽기를 기록하지 않아 이메일·비밀번호 해시·2FA 비밀정보 등의 접근은 배제할 수 없다고 밝혔다. 비공개 패키지·문서 열람도 완전히 배제하지 못한다. **변조 증거가 없다는 설명과 정보 열람 가능성을 구분해야 한다.** [확인된 사항과 조사 한계](https://hex.pm/blog/security-incident-on-hexpm)

**대응 포인트:** Hex 이용자는 비밀번호를 변경하고, 보안 설정의 Authenticator App에서 **Setup New App**으로 2FA를 재설정한 뒤 새 복구 코드를 보관하자. 운영자는 새 레지스트리 서명 체계를 지원하는 클라이언트가 나오면 갱신하고, 그전까지 패키지는 **repo.hex.pm**에서만 받도록 안내한다. 새 클라이언트가 이미 배포됐다고 가정하지 말고 공식 공지를 확인해야 한다. [계정·클라이언트 대응 안내](https://hex.pm/blog/security-incident-on-hexpm)

### 2. CISA, AntiCsrf·Drupal·Optimizely 실제 악용 취약점 3건 추가

**핵심 요약:** CISA는 11월 24일 다음 3건을 **알려진 악용 취약점 목록 KEV**에 추가했다. 이는 신규 패치 3건 발표가 아니라 실제 악용 증거에 따른 목록 갱신이다. 공식 데이터의 조치 기한은 모두 **11월 27일**, 포렌식 초기 점검 표시는 모두 **Yes**다. 이 기한은 미 연방 민간기관 대상이며 국내 모든 조직에 같은 법적 기한을 부여하는 것은 아니다. [CISA 신규 등재 공지](https://www.cisa.gov/news-events/alerts/2026/11/24/cisa-adds-three-known-exploited-vulnerabilities-catalog) · [공식 KEV 데이터](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json)

| 취약점 | 영향과 대응 방향 |
| --- | --- |
| **CVE-2026-131914 — Idunno AntiCsrf** | 신뢰할 수 없는 데이터 역직렬화로 비인증 원격 코드 실행 가능. Mandiant는 유지관리자·공식 패치가 없는 레거시 구성요소라며 지원되는 CSRF 방어 수단으로 교체하도록 권고한다. |
| **CVE-2026-132165 — Drupal Core** | 특정 조건에서 설치기를 통한 사이트 탈취·코드 실행 가능. 해당 지원 분기의 수정 버전으로 업데이트하고 설치기 접근도 보호해야 한다. |
| **CVE-2026-132224 — Optimizely Web Experimentation** | 가입 흐름의 결함으로 기존 이용자 사칭과 Project JavaScript 변경 가능. 악성 JavaScript가 고객 사이트 방문자의 브라우저에 전달될 수 있어 공급업체 지침과 변경 이력 확인이 중요하다. |

표의 영향 설명은 [CISA KEV 원본](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json), 교체·수정 지침은 [Mandiant 공식 보고서](https://github.com/mandiant/Vulnerability-Disclosures/blob/master/2026/MNDT-2026-0048.md)와 [Drupal 공식 권고](https://www.drupal.org/sa-core-2026-017)에 근거한다.

**적용 포인트:** Drupal 권고는 **11.4.13·11.3.22·10.6.22**를 해당 분기의 수정 버전으로 안내한다. 업데이트와 함께 설치기 보호가 필요하며, 웹 서버의 settings.php 쓰기 권한 제한은 일부 공격 경로를 완화한다. Idunno AntiCsrf는 모든 ASP.NET의 공통 문제가 아니라 해당 레거시 모듈 사용 여부를 찾아 대응해야 하는 사안이다. [Drupal 권고](https://www.drupal.org/sa-core-2026-017) · [영향 구성요소·교체 지침](https://github.com/mandiant/Vulnerability-Disclosures/blob/master/2026/MNDT-2026-0048.md)

**대응 포인트 — 편집부 제안:** 인터넷 노출 자산과 내장 라이브러리 사용 여부를 우선 확인하고, 수정·교체와 패치 전 침해 흔적 점검을 함께 계획하자. 세 항목의 랜섬웨어 캠페인 사용 여부는 KEV에서 모두 **Unknown**이므로 하나의 랜섬웨어 캠페인으로 묶어 단정하지 않는다. [CISA의 점검 요구·관측 범위](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json)
