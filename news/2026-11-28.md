## IT 이슈

### 1. 래블업, 로컬 모델과 파일 작업을 결합한 AI:GO 2.0 출시

**핵심 요약:** 래블업은 27일 AI:GO 2.0을 발표했습니다. 언어·시각·이미지·음성 AI 모델을 PC에서 실행하고, 대화창에 작업 폴더를 연결하면 Cowork 에이전트가 허용된 폴더의 파일을 읽고 수정하는 구조입니다. 지원 환경은 Apple Silicon 기반 macOS 15 이상, 64비트 Windows 10·11, Linux이며, 개인용 앱은 가입 없이 무료로 내려받을 수 있다는 설명입니다. [공식 발표](https://lablup.com/press/2026-11-lablup-launches-ai-go-v2)

**왜 중요한가:** 모델과 실제 파일 작업을 한 앱에서 연결한다는 점이 변화입니다. 회사는 내장 벤치마크로 PC별 모델 속도를 확인할 수 있고, 복잡한 업무에서는 역할별 에이전트를 묶는 Squad 기능을 제공한다고 밝혔습니다. 기업용 유료 제품에는 조직 정책 배포와 장치 등록, 망분리 운영 지원을 제시했습니다. [공식 발표](https://lablup.com/press/2026-11-lablup-launches-ai-go-v2)

**권한·보안 범위:** 회사에 따르면 코드 실행에는 MXC 기반 운영체제 격리를 통합했으며, 지정 폴더 밖의 접근과 네트워크 연결을 기본 차단합니다. 결제·전송·삭제 등 민감 작업에는 사용자 승인을 요구한다고 설명했습니다. 이는 공급업체의 기능 설명으로, 독립적인 보안 검증 결과로 제시된 것은 아닙니다. [공식 발표](https://lablup.com/press/2026-11-lablup-launches-ai-go-v2)

**관찰 포인트 — 편집부 제안:** 실제 도입 전 사용 중인 운영체제에서 폴더 권한과 승인 동작을 확인하십시오. 대표 문서와 파일 복사본으로 모델 속도, 편집 정확도, 복구 절차를 시험할 만합니다.

### 2. CloudWatch, AWS 지표를 PromQL로 조회하는 기본 OpenTelemetry 정보 보강 제공

**핵심 요약:** AWS는 27일 CloudWatch의 AWS 서비스 지표에 대한 기본 OpenTelemetry 정보 보강을 추가 비용 없이 제공한다고 발표했습니다. EC2의 인스턴스 식별자처럼 리소스를 식별할 수 있는 지표를 대상으로, ARN·클라우드 제공자·리전·계정 ID 등의 속성과 원래 서비스 정보를 붙입니다. 기존 CloudWatch 차원은 데이터 포인트 속성으로 변환되며 PromQL로 조회할 수 있습니다. [AWS 발표](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-opentelemetry-enrichment/)

**왜 중요한가:** AWS 서비스 지표를 OpenTelemetry 형식과 PromQL 조회 방식으로 활용할 수 있습니다. 기존 CloudWatch API를 통한 지표 접근도 유지됩니다. CloudWatch Omni를 설정하면 기본 정보 보강이 자동 활성화되고, 계정별로 콘솔·명령행 도구·SDK에서 직접 켤 수도 있습니다. 제공 지역은 CloudWatch OpenTelemetry 지표가 지원되는 리전입니다. [AWS 발표](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-opentelemetry-enrichment/)

**비용·범위 확인:** “추가 비용 없음”은 이번 **기본 정보 보강 기능**에 대한 설명입니다. AWS 리소스 태그를 PromQL 레이블로 조회하려면 리소스 태그 정보 보강을 선택해야 하며, 이 기능은 별도 과금됩니다. 발표만으로 CloudWatch 사용 전체가 무료라고 해석해서는 안 됩니다. [AWS 발표](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-opentelemetry-enrichment/)

**관찰 포인트 — 편집부 제안:** 기존 대시보드의 차원과 변환된 속성이 어떻게 대응되는지 먼저 확인하십시오. 태그 기반 조회가 필요한 지표만 추려 과금 방식과 함께 검토하는 편이 좋습니다.

## 보안 이슈

### 1. easyDNS, 고객 정보 노출 범위 공개…easyMail 비밀번호와 저장한 AWS 키 확인 필요

**핵심 요약:** easyDNS는 27일 공지에서, 전날 자사 AWS 계정의 무단 로그인과 easyRoute53 연동용 고객 AWS 키의 무단 사용 보고를 조사하다가 노출 범위가 키 외의 정보까지 확대됐음을 확인했다고 밝혔습니다. 이번 공지는 26일 긴급 키 교체 요청의 후속 조사 결과입니다. [27일 공지](https://easydns.com/blog/2026/11/27/easydns-data-breach/), [26일 긴급 권고](https://easydns.com/blog/2026/11/26/urgent-rotate-aws-keys-stored-in-easydns-cp-immediately/)

**영향 범위:** 고객에 따라 이름·이메일·주소·전화번호와 제한적인 청구 정보가 포함될 수 있습니다. easyMail 이용자의 메일함 비밀번호는 솔트 없는 SHA-256 해시로 저장돼 있었으며, 회사는 약한 비밀번호가 해독될 수 있다고 설명했습니다. 정기 결제 고객의 카드 끝 4자리·유효기간 등이 포함될 수 있지만 전체 카드번호는 유출되지 않았다는 설명입니다. [회사 공지](https://easydns.com/blog/2026/11/27/easydns-data-breach/)

**구분할 점:** 회사는 easyDNS 제어판 비밀번호·해시와 고객 REST API 키는 노출되지 않았다고 밝혔습니다. 도메인·DNS·이메일 등의 운영은 유지되지만 easyRoute53 연동은 중단된 상태라고 안내했습니다. 조사와 사후 분석은 계속 진행 중입니다. [회사 공지](https://easydns.com/blog/2026/11/27/easydns-data-breach/)

**대응 포인트:** easyRoute53 연동을 위해 easyDNS에 AWS 키를 저장한 이용자는 해당 키를 즉시 교체하라는 기존 권고를 확인해야 합니다. easyMail 이용자는 메일함 비밀번호를 변경해야 하며, 회사는 다음 제어판 로그인에서도 비밀번호 재설정을 요구한다고 밝혔습니다. **편집부 제안:** AWS 키의 최근 사용 기록을 점검하고, 노출된 연락처를 이용한 피싱에도 주의하십시오. [키 교체 권고](https://easydns.com/blog/2026/11/26/urgent-rotate-aws-keys-stored-in-easydns-cp-immediately/), [후속 공지](https://easydns.com/blog/2026/11/27/easydns-data-breach/)

### 2. 캐나다, Mitel OpenScape 4000 업데이트 권고…제품·버전별 조치 확인

**핵심 요약:** 캐나다 사이버보안센터는 27일 권고 AV26-1212를 통해 OpenScape 4000과 OpenScape 4000 Manager의 업데이트를 안내했습니다. 연결된 제조사 권고 MISA-2026-0013은 18일 공개됐으며, 플랫폼 구성요소의 무단 접근과 명령 삽입 문제를 다룹니다. 이번 새 정부 권고와 기존 기술 공개를 구분할 필요가 있습니다. [정부 권고](https://www.cyber.gc.ca/en/alerts-advisories/mitel-security-advisory-av26-1212), [제조사 권고](https://www.mitel.com/support/security-advisories/mitel-product-security-advisory-misa-2026-0013)

**왜 중요한가:** Mitel은 인증 없이 민감 정보에 접근하거나 시스템 명령을 실행할 수 있는 문제를 설명했습니다. 세 문제 중 하나는 인접 네트워크 접근이 조건이며, 제조사가 부여한 CVSS 3.1 점수는 각각 10.0·10.0·9.6입니다. 제조사 식별자는 `MTLVULN-1785`·`MTLVULN-1786`·`MTLVULN-1793`이고, 확인한 공지에는 CVE가 요청됐으나 아직 배정되지 않았다고 적혀 있습니다. [제조사 권고](https://www.mitel.com/support/security-advisories/mitel-product-security-advisory-misa-2026-0013)

**대응 포인트:** 기본 수정 경로는 **V11 R2.14 이상**으로의 업그레이드입니다. 일부 구버전에는 PLT HF5 등 별도 핫픽스·패치 경로가 있으므로, 제품별 영향 버전 표와 KB000129263을 함께 확인해야 합니다. 즉시 적용이 어렵다면 제조사가 안내한 Security Mode의 제한 접근을 임시 대응으로 검토할 수 있습니다. 설치 세부 사항은 공식 기술지원이나 공인 파트너를 통해 확인하도록 안내됐습니다. [제조사 조치 안내](https://www.mitel.com/support/security-advisories/mitel-product-security-advisory-misa-2026-0013)

**관찰 포인트 — 편집부 제안:** 통신 시스템과 관리 서버를 각각 자산 목록에서 확인하고, 관리 경로의 접근 범위를 점검하십시오. 이번 자료에는 실제 악용 확인을 명시한 내용이 없어, 악용 중인 취약점으로 단정하지 않았습니다. [확인한 정부 권고](https://www.cyber.gc.ca/en/alerts-advisories/mitel-security-advisory-av26-1212), [제조사 권고](https://www.mitel.com/support/security-advisories/mitel-product-security-advisory-misa-2026-0013)
