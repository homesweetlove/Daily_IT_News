## IT 이슈

### 1. AWS, 역할 뒤에 있는 실제 사용자·워크로드 신원을 더 넓게 전달

**핵심 요약:** AWS는 25일 신원 정보 전파(TIP)를 IAM 페더레이션과 IAM Roles Anywhere로 확대했습니다. 지원 경로에서 요청의 원래 사용자·워크로드 신원을 IAM 정책 조건과 CloudTrail 기록에 활용할 수 있습니다. SAML·OIDC 연동은 신원과 선택적인 실행 시점 속성을 역할 세션에 연결하며, Roles Anywhere는 X.509 인증서에서 신원을 가져옵니다. [AWS 발표](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-iam/)

**왜 중요한가:** 역할을 연이어 사용하는 환경에서도 요청의 출발 주체를 식별하는 데 도움이 됩니다. AWS는 지원 경로에서 역할별 신뢰 정책을 따로 갱신하지 않고 신원 정보가 유지된다고 설명했습니다. 외부 서비스가 요청 출발 주체를 확인하도록, TIP 세션 정보를 포함한 AWS 서명 JWT를 요청하는 기능도 제공합니다. 적용 범위는 지원 AWS 서비스·경로를 기준으로 확인해야 합니다. [AWS 발표](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-iam/)

**관찰 포인트 — 편집부 제안:** 대표적인 사용자 로그인과 외부 워크로드 요청을 시험해, 정책 조건에 사용할 신원 속성과 감사 로그의 표시 내용을 함께 확인하십시오. 여러 역할이 같은 업무를 수행한다면 출발 주체별 권한 구분이 필요한지 검토할 만합니다.

### 2. EC2 M9gd 서울 리전 제공 시작…로컬 저장장치가 필요한 범용 작업에 선택지

**핵심 요약:** AWS는 25일부터 서울 리전에서 Graviton5 기반 M9gd 인스턴스를 제공한다고 발표했습니다. 범용 컴퓨팅에 로컬 NVMe SSD 블록 저장장치를 결합하며, 임시 파일·작업 공간·캐시처럼 빠른 로컬 저장장치가 필요한 용도를 제시했습니다. 온디맨드·스팟·Savings Plans 등으로 구매할 수 있습니다. [AWS 발표](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-ec2-m9gd-asiapacific-seoul/)

**왜 중요한가:** 이번 소식은 인스턴스 자체의 최초 출시보다 **서울 리전으로의 제공 범위 확대**에 초점이 있습니다. AWS는 M8gd 대비 컴퓨팅 성능이 최대 25% 높다고 설명했지만, 이는 공급업체가 제시한 최대 수치입니다. 개별 서비스의 성능이나 비용 절감률을 그대로 보장하는 수치로 해석해서는 안 됩니다. [AWS 발표](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-ec2-m9gd-asiapacific-seoul/)

**관찰 포인트 — 편집부 제안:** 전환 후보는 실제 애플리케이션·캐시 작업으로 비교하십시오. 처리량뿐 아니라 지연시간, 시간당 비용, 데이터 복구 절차를 함께 점검한 뒤 운영 환경 적용 여부를 결정하는 편이 좋습니다.

## 보안 이슈

### 1. Microsoft “ARTEX 악용은 기존 공격 기법을 기계 속도로 연결하는 위협”

**핵심 요약:** Microsoft는 25일 공개 분석에서, 7월 출시된 AI 침투 테스트 프레임워크 ARTEX가 국가 배후 및 금전 목적 공격자에게 악용되고 있다고 밝혔습니다. 공격자가 목표와 범위를 정하면 여러 에이전트가 정찰·취약점 악용·자격 증명 공격 등을 이어 수행한다는 설명입니다. 이는 기존 활동에 대한 새 분석이며, 모든 공격이 25일 시작됐다는 의미는 아닙니다. [Microsoft 분석](https://www.microsoft.com/en-us/security/blog/2026/11/25/what-defenders-need-to-know-artex-agentic-ai-framework-threat-actors-abuse/)

**왜 중요한가:** 보고서는 새로운 공격 기법의 등장보다 **기존 도구의 빠른 조합과 재시도**를 강조합니다. 고정 IP나 사용자 에이전트보다 짧은 시간의 다양한 탐색, 실패 후 변형 재시도, 침투 직후 다음 단계로 넘어가는 행동이 유용한 단서입니다. 다만 비슷한 행동은 다른 자동화 프레임워크에서도 나타나므로, 이것만으로 ARTEX나 AI 사용을 단정할 수 없습니다. [Microsoft 분석](https://www.microsoft.com/en-us/security/blog/2026/11/25/what-defenders-need-to-know-artex-agentic-ai-framework-threat-actors-abuse/)

**대응 포인트:** Microsoft는 외부 노출 축소, 비밀정보 보호, 내부 이동 경로 제한을 권고했습니다. 웹 서버가 명령 셸을 실행하거나 웹 경로에 새 스크립트가 생기는 현상도 점검 대상으로 제시했습니다. **편집부 제안:** 이 신호들을 개별 경보로만 보지 말고 짧은 시간의 연속 행동으로 묶어 조사하십시오. [Microsoft 분석](https://www.microsoft.com/en-us/security/blog/2026/11/25/what-defenders-need-to-know-artex-agentic-ai-framework-threat-actors-abuse/)

### 2. 캐나다, GeoServer 취약점 두 건의 실제 악용 경고…이미 나온 수정 버전 적용 필요

**핵심 요약:** 캐나다 사이버보안센터는 25일 권고 AV26-1207을 통해 `CVE-2026-120705`와 `CVE-2026-129243`가 실제 악용되고 있다는 공개 보도를 안내했습니다. GeoServer 프로젝트는 각각 인증 없는 WFS XML 삽입과 서비스 보안 규칙 우회로 설명합니다. 악용 경고의 근거와 기술 설명의 출처를 구분해 볼 필요가 있습니다. [정부 권고](https://www.cyber.gc.ca/en/alerts-advisories/geoserver-security-advisory-av26-1207), [프로젝트 공지](https://geoserver.org/vulnerability/2026/11/23/cve-update.html)

**왜 중요한가:** 프로젝트는 이 문제들을 관리자 세션 위조·코드 실행으로 이어질 수 있는 여러 단계의 공격 체인과 함께 공개했습니다. 두 CVE 각각이 모든 환경에서 단독으로 인증 없는 원격 코드 실행을 일으킨다고 확대 해석해서는 안 됩니다. 수정 버전은 10월에 배포됐고, 세부 공지는 23일, 이번 정부 악용 경고는 25일 나왔습니다. [프로젝트 공지](https://geoserver.org/vulnerability/2026/11/23/cve-update.html), [정부 권고](https://www.cyber.gc.ca/en/alerts-advisories/geoserver-security-advisory-av26-1207)

**대응 포인트:** 프로젝트가 안내한 수정 버전은 **3.0.2·2.28.6·2.27.7**입니다. 각 계열의 이전 버전을 운영한다면 해당 수정 버전 또는 이를 포함한 지원 버전으로의 업데이트를 우선 검토하십시오. **편집부 제안:** 인터넷에 공개한 서버부터 점검하고, 업데이트와 함께 의심스러운 요청 및 관리자 설정 변경 기록을 살펴보십시오. [프로젝트 공지](https://geoserver.org/vulnerability/2026/11/23/cve-update.html)

### 3. CISA, 실제 악용 취약점 10건 등재…제품별 조치 기한·침해 점검 요구 구분

**핵심 요약:** CISA는 25일 실제 악용 증거를 바탕으로 KEV 목록에 10건을 추가했습니다. Danfoss AK-SM 800A 계열 3건, HPE Juniper Session Smart 계열 1건, Mitel MiCollab 5건, Vates Xen Orchestra 1건입니다. 오래된 CVE도 이번 추가 대상에 포함됐습니다. [CISA 공지](https://www.cisa.gov/news-events/alerts/2026/11/25/cisa-adds-10-known-exploited-vulnerabilities-catalog)

아래는 25일자 공식 목록의 항목별 값입니다. **기한은 미국 연방 민간 행정부 기관(FCEB)에 적용되는 지침의 조치 기한**이며, 일반 기업의 법적 의무 기한을 뜻하지 않습니다. [공식 목록](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json), [적용 범위 설명](https://www.cisa.gov/news-events/alerts/2026/11/25/cisa-adds-10-known-exploited-vulnerabilities-catalog)

| --- | --- | --- | --- |
| Danfoss AK-SM 800A | CVE-2023-25914, CVE-2023-25915 | 11월 28일 | Yes |
| Danfoss AK-SM 800A | CVE-2025-41450 | 12월 9일 | No |
| HPE Juniper Session Smart Conductor / Router | CVE-2026-103406 | 11월 28일 | Yes |

**왜 중요한가:** 같은 제품에서도 조치 기한과 포렌식 요구가 다릅니다. 10건 모두 랜섬웨어 캠페인 사용 여부는 `Unknown`으로 기록돼 있어, 랜섬웨어 악용까지 확인됐다고 표현할 수는 없습니다. `No`는 해당 항목에 별도 포렌식 요구가 없다는 목록 값이지, 미침해를 보장하는 판정이 아닙니다. [공식 목록](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json)

**대응 포인트 — 편집부 제안:** 자산 목록과 CVE를 대조하고, KEV 각 항목의 공급업체 권고 링크에서 설치 버전별 조치를 확인하십시오. 외부 노출 자산을 먼저 처리하고, 침해가 의심되면 패치 적용과 침해 조사·복구를 함께 진행하십시오.
