## IT 이슈

### 1. VS Code 1.146 출시…에이전트 관리 확장, Local harness 종료 일정 제시

**핵심 요약:** Microsoft는 11월 11일 **VS Code 1.146 Stable**을 출시했습니다. 에이전트 세션을 주의가 필요한 작업 중심으로 모아 보는 Inbox mode는 **실험 기능**, 별도 Chat windows와 모델 비교 기능은 **미리 보기**로 안내됐습니다. 안정판 출시와 개별 기능의 실험·미리 보기 상태를 구분해야 합니다. [공식 릴리스 노트](https://code.visualstudio.com/updates/v1_146)

**운영에 미치는 변화:** 이번 버전부터 **Local harness가 사용 중단 단계**에 들어가며, **2027년 2월 제거 예정**입니다. 남은 기간에는 기능이 동결되고 새 기능·개선은 Copilot harness에 집중됩니다. 공식 안내에 따르면 Copilot harness는 이미 새 세션의 기본값입니다. [전환 일정](https://code.visualstudio.com/updates/v1_146)

**왜 중요한가 — 편집부 해석:** 개발 환경에서 에이전트 사용이 늘면 개별 채팅보다 여러 작업의 상태와 권한을 관리하는 일이 중요해집니다. 기존 Local harness에 맞춘 조직 설정이나 사용자 정의 작업이 있다면 제거 시점에 앞서 호환성을 검토할 필요가 있습니다.

**대응·관찰 포인트:** Local harness 사용자는 공식 전환 가이드에 따라 기존 대화와 사용자 정의 구성을 점검하는 것이 좋습니다. Inbox mode 등 선택 기능은 기본 비활성화 여부를 확인한 뒤 시험 적용하세요. [릴리스 노트와 전환 가이드 링크](https://code.visualstudio.com/updates/v1_146)

### 2. Databricks, 유럽·중동에 3년간 약 30억 달러 투자 계획

**핵심 요약:** Databricks는 11월 11일 유럽·중동에서 **향후 3년간 약 30억 달러**를 투자하겠다고 발표했습니다. 지역 연구개발과 엔지니어·AI 전문가·고객 지원 인력 확대가 중심입니다. EMEA 인력을 같은 기간 약 **50% 늘리고**, **2030년까지 EMEA 학생·전문가 약 50만 명을 교육**한다는 목표도 제시했습니다. 투자액의 지역 범위와 교육 목표의 지역 범위는 발표상 서로 다릅니다. [Databricks 공식 발표](https://www.databricks.com/company/newsroom/press-releases/databricks-invest-3-billion-across-europe-and-middle-east)

**왜 중요한가 — 편집부 해석:** 기업용 AI의 확산에는 모델뿐 아니라 데이터 기반과 현지 기술 지원, 운영 인력이 필요합니다. 이번 계획은 유럽·중동 기업 고객을 위한 도입·운영 지원 경쟁이 커지고 있음을 보여주는 사례로 볼 수 있습니다.

**관찰 포인트:** 발표는 **향후 투자·채용·교육 계획**입니다. 30억 달러가 이미 집행됐거나 교육 인원이 이미 배출됐다는 의미는 아닙니다. 이용 기업은 실제 지역별 인력 배치와 지원 조건, 계약상 데이터 처리·운영 조건을 확인하는 것이 좋습니다. [계획과 목표 원문](https://www.databricks.com/company/newsroom/press-releases/databricks-invest-3-billion-across-europe-and-middle-east)

## 보안 이슈

### 1. Git 취약점 6건 수정…내장 Git을 사용하는 앱까지 업데이트 확인 필요

**핵심 요약:** 11월 10일 발표된 Git 보안 업데이트에 대해 11월 11일 후속 보도와 앱 배포가 이어졌습니다. 대표 문제인 **CVE-2026-111760**은 악성 저장소를 **재귀 복제**할 때 공격자 코드 실행으로 이어질 수 있습니다. 다른 수정에는 참조 처리, 병합, 바이너리 패치, fast-import 관련 문제가 포함됩니다. [11월 11일 후속 보도](https://www.helpnetsecurity.com/2026/11/11/git-project-security-updates/) · [GitHub 공식 설명](https://github.blog/open-source/git/git-security-vulnerabilities-announced-7/)

**수정 버전:** 공식 릴리스 노트는 **Git 2.56.1**과 유지보수 계열별 **2.55.1·2.54.1·2.53.1·2.52.1·2.51.3·2.50.2**에서 해당 6건을 수정했다고 설명합니다. [Git 프로젝트 릴리스 노트](https://github.com/git/git/blob/v2.56.1/Documentation/RelNotes/2.56.1.adoc)

**이번 조사 범위의 후속 변화:** GitHub Desktop은 11월 11일 **3.6.12-beta1**을 공개하고 내장 Git을 **2.56.1**로 올렸습니다. 이는 **사전 릴리스**이며, 해당 페이지를 근거로 Desktop 안정판까지 업데이트가 완료됐다고 판단해서는 안 됩니다. [GitHub Desktop 공식 릴리스](https://github.com/desktop/desktop/releases/tag/release-3.6.12-beta1)

**대응:** 운영체제·배포판 또는 Git 공급자가 제공하는 수정판을 적용하고, Git을 자체 내장한 앱과 저장소를 처리하는 자동화 서버도 별도로 확인하세요. 즉시 업데이트가 어려우면 신뢰하지 않는 저장소의 재귀 복제와 외부 병합 입력·바이너리 패치·fast-import 스트림 처리를 피하도록 공식 공지는 권고합니다. [제조사·개발자 대응 지침](https://github.blog/open-source/git/git-security-vulnerabilities-announced-7/)

**왜 중요한가 — 편집부 해석:** 터미널의 Git 하나만 업데이트해도 충분한 환경인지 확인해야 합니다. IDE·데스크톱 앱·자동화 도구가 각각 다른 Git 실행 파일을 사용할 수 있으므로 실제 호출되는 경로와 버전까지 확인하는 것이 좋습니다.

### 2. Mitel MiVoice MX-ONE, LAN 접근자의 관리자 인증 우회 등 3건 공개

**핵심 요약:** Mitel은 11월 11일 **MISA-2026-0011** 권고를 공개했습니다. 가장 심각한 **MTLVULN-1860**은 LAN에 접근할 수 있는 미인증 공격자가 Service Node Manager의 관리자 인증을 우회해 PBX 전화 라우팅·서비스 구성을 열람·변경할 수 있는 문제이며, **CVSS 9.4**로 평가됐습니다. 표기된 MTLVULN 번호는 **제조사 내부 추적 번호**로, 공식 공지는 CVE 번호가 아직 배정되지 않았다고 설명합니다. [Mitel 공식 권고](https://www.mitel.com/support/security-advisories/mitel-product-security-advisory-misa-2026-0011)

**영향과 조건:** 함께 공개된 정보 노출 문제 **MTLVULN-1858**은 인증된 사용자와 LAN 접근이, 명령 주입 문제 **MTLVULN-1859**는 관리자 권한과 LAN 접근이 필요합니다. 각 취약점의 인증·접근 조건을 구분해 영향 평가를 해야 합니다. [공격 전제와 영향](https://www.mitel.com/support/security-advisories/mitel-product-security-advisory-misa-2026-0011)

**대응:** 영향 범위는 **MiVoice MX-ONE 8.0(8.0.0.33)~8.2 SP1(8.2.1.0.14)**입니다. Mitel은 **PM/SNM 8.2 SP0 HF5 또는 8.2 SP1 HF2 이상**의 핫픽스 적용을 권고하며, 8.3 이상은 제공될 때 업그레이드하도록 안내합니다. 실제 적용 경로는 유지보수 파트너와 확인하세요. [영향 버전·수정 방안](https://www.mitel.com/support/security-advisories/mitel-product-security-advisory-misa-2026-0011)

**왜 중요한가 — 편집부 해석:** 통신 관리 기능이 침해되면 업무용 전화의 라우팅·서비스 설정이 영향을 받을 수 있습니다. 내부망 접근이라는 조건을 고려해 관리 인터페이스의 접근 범위도 함께 점검할 필요가 있습니다.
