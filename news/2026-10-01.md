## IT 이슈

### 1. Synopsys·OpenAI, 칩 설계용 ‘GPT-Synopsys’ 공동 개발

**핵심 요약:** Synopsys는 OpenAI와 칩 설계 작업에 특화된 AI 모델을 개발하고 수익을 공유하는 계약을 발표했습니다. 모델은 회로 기술부터 트랜지스터 배치까지 설계 과정의 작업을 지원하고, Synopsys 도구를 사용해 최적화를 돕도록 훈련됩니다. OpenAI는 도구 학습을 위한 구독료를 지급하며, 고객 사용 시 설계 개선 정도에 따라 양사가 수익을 나누는 구조입니다. 모델의 결과는 전통적인 Synopsys 검증 도구로 다시 확인합니다. [Reuters 원문](https://www.reuters.com/business/synopsys-openai-strike-deal-develop-ai-model-chip-design-work-2026-09-30/) [1]

**왜 중요한가:** 범용 AI가 전문 설계 도구와 결합하는 사례입니다. 칩 설계는 물리적 제약과 정확성 검증이 중요하므로, 생성 결과를 기존 도구로 검증하는 구조가 실제 도입의 핵심이 될 것으로 보입니다.

**관찰 포인트:** 설계 기간 단축과 전력·성능·면적 개선이 실제 고객 프로젝트에서 재현되는지, 검증 비용까지 포함해 경제성이 있는지 살펴볼 필요가 있습니다. 기사에서 제품의 일반 제공 일정은 확인되지 않았습니다.

### 2. HPE, Vultr에 AMD AI 랙 공급…12억 달러 주문 확보

**핵심 요약:** HPE는 클라우드 업체 Vultr의 미국 데이터센터에 AMD Helios AI 랙을 공급하는 12억 달러 주문을 발표했습니다. 랙에는 AI 칩과 HPE의 네트워크 스위치·소프트웨어가 포함됩니다. HPE는 네트워킹 부문의 2026~2029 회계연도 연평균 매출 성장 전망을 10%대 후반으로 제시했습니다. [Reuters 원문](https://www.reuters.com/business/hpe-boosts-networking-growth-outlook-gets-12-billion-ai-order-cloud-firm-vultr-2026-09-30/) [2]

**왜 중요한가:** AI 인프라 구매가 가속기뿐 아니라 랙·네트워크·운영 소프트웨어를 묶는 형태로 확대되고 있습니다. AMD 기반 대규모 공급은 클라우드 고객에게 하드웨어 선택지를 늘리는 움직임으로 해석할 수 있습니다.

**관찰 포인트:** 실제 설치·가동 일정과 워크로드별 성능, 네트워크 병목, 운영비가 중요합니다. 주문 금액을 이미 인식된 매출이나 완료된 구축 규모로 해석해서는 안 됩니다.

### 3. Google, Gemini 4 세대의 상위 모델 ‘Argon’ 발표

**핵심 요약:** Google은 Gemini 4 세대를 이끌 새 상위 AI 모델 ‘Argon’을 발표했습니다. 회사 대변인은 기존 Pro 계열보다 큰 모델이라고 설명했습니다. 일부 사이버보안 파트너에게 제공하며 미국 정부의 출시 전 모델 접근 절차에도 참여하지만, 일반 공개 시점은 제시하지 않았습니다. Google은 Gemini 3.5 Pro를 출시하지 않을 계획이라고 밝혔습니다. [Reuters 원문](https://www.reuters.com/legal/litigation/google-announces-gemini-4-flagship-ai-model-after-months-delays-2026-09-30/) [3]

**왜 중요한가:** 복잡한 코딩·보안 작업을 겨냥한 모델 경쟁과 출시 전 평가가 함께 진행되는 사례입니다. 다만 성능 비교는 Google이 발표한 벤치마크에 기반하므로 독립적인 검증과 구분해야 합니다.

**관찰 포인트:** 공개 일정, 가격, 이용 조건, 외부 평가 결과가 나오기 전에는 도입 가능성과 비용을 판단하기 어렵습니다. 오늘의 발표를 모든 사용자가 이용할 수 있는 제품 출시로 받아들이지 않도록 주의해야 합니다.

## 보안 이슈

### 1. Cisco SD-WAN Manager 인증 우회 취약점, 실제 공격 확인

**핵심 요약:** Cisco는 9월 30일 13:00 UTC(22:00 KST) 공식 권고에서 **CVE-2026-76504**를 공개했습니다. CVSS 3.1 점수는 **9.8**입니다. HTTP 요청의 URI 인코딩을 잘못 처리해 인증하지 않은 원격 공격자가 API에 관리자 권한으로 접근할 수 있습니다. 시스템 구성에 관계없이 취약 버전의 Catalyst SD-WAN Manager가 영향을 받으며, Cisco는 9월 중 실제 악용을 확인했습니다. [Cisco 공식 권고](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-sdwan-webauth-xr8beuuU) [4]

**영향:** 중앙 네트워크 관리 시스템의 관리자 권한을 잃을 수 있어 관리 대상 장비와 설정까지 영향을 조사해야 합니다. BleepingComputer는 CISA가 이를 KEV 목록에 추가하고 미국 연방기관에 10월 3일까지 조치하도록 요구했다고 보도했습니다. [보도 원문](https://www.bleepingcomputer.com/news/security/cisco-warns-of-new-sd-wan-authentication-bypass-zero-day-exploited-in-attacks/) [5]

**대응:** 사용 계열에 맞춰 다음 최초 수정 버전 또는 이후의 적절한 수정 버전으로 업데이트해야 합니다. Cisco는 취약점 자체를 해결하는 우회책이 없다고 설명합니다.

| 사용 계열 | 최초 수정 버전 |
| --- | --- |
| 20.9 | 20.9.10.1 |
| 20.12 | 20.12.8.2 |
| 20.15 | 20.15.6.1 |
| 20.18 | 20.18.4.1 |
| 26.1 | 26.1.2.1 |
| 26.2 | 26.2.1 |

20.9 이전 계열은 수정된 계열로 이전해야 합니다. 관리 인터페이스 접근을 신뢰할 수 있는 호스트로 제한하고, 공식 권고의 `serviceproxy-access.log`·`vmanage-server.log` 점검 절차로 의심스러운 인증 요청을 조사하세요. Cisco 관리형 클라우드에는 별도의 수정 릴리스가 적용되며 공식 권고는 사용자 조치가 필요하지 않다고 명시합니다. [4]

### 2. TeamViewer, 원격 세션 권한 우회 등 취약점 5건 수정

**핵심 요약:** 9월 30일 보도된 TeamViewer 권고는 Full Client·Host 및 관련 모듈의 취약점 5건을 다룹니다. 공식 공지는 9월 29일자로 게시됐으며, 최대 심각도는 CVSS **8.8(High)**입니다. **CVE-2026-92370**은 원격 세션 설정에서 사용자가 제한한 기능의 권한을 우회해 허용되지 않은 동작을 수행하고 코드 실행으로 이어질 수 있는 문제입니다. 다른 문제는 로컬 권한 상승이나 조작된 세션 녹화 파일 처리 등에 관련됩니다. 플랫폼·버전별 영향은 서로 다릅니다. [TeamViewer 공식 공지](https://www.teamviewer.com/en-us/resources/trust-center/security-bulletins/tv-2026-1010/) [6][7]

**영향:** 원격 지원 도구의 접근 제한과 시스템 권한 경계가 약해질 수 있습니다. 업체는 공지 당시 공개된 악용이나 실제 공격을 인지하지 못했다고 밝혔으므로, Cisco 사례처럼 실제 악용이 확인된 취약점과 구분해야 합니다. [6]

**대응:** 일반 배포 계열은 **15.82 이상**의 수정된 버전으로 업데이트하세요. 레거시·유지보수 계열은 공식 공지의 플랫폼별 패치 버전을 확인해야 합니다. Client뿐 아니라 상시 실행되는 Host의 업데이트 여부도 확인하고, 출처가 불분명한 세션 녹화 파일은 열지 않는 것이 좋습니다.

### 3. Microsoft Entra ID, 10월 중 로그인 페이지 외부 스크립트 차단

**핵심 요약:** 9월 30일 BleepingComputer는 Microsoft가 Entra ID 브라우저 로그인에 강화된 **콘텐츠 보안 정책(CSP)**을 10월 중순부터 적용해 10월 말까지 배포할 예정이라고 보도했습니다. 신뢰하는 Microsoft 호스팅 스크립트만 허용해 외부 스크립트 삽입과 XSS 위험을 줄이는 변경입니다. 새 침해사고 발표가 아니라, 기존 계획의 적용 일정에 관한 안내입니다. [보도 원문](https://www.bleepingcomputer.com/news/security/microsoft-to-block-entra-id-script-injection-attacks-starting-october/) [8]

**영향:** 로그인 페이지에 코드를 주입하는 확장 프로그램이나 보조 도구가 작동하지 않을 수 있습니다. 기사에 따르면 변경은 기본 적용되며 별도 테넌트 설정은 필요하지 않습니다. 대상은 `login.microsoftonline.com`을 사용하는 브라우저 로그인 경험입니다. [8]

**대응:** 사내 로그인 흐름과 사용 중인 브라우저 확장을 사전 테스트하세요. 개발자 콘솔의 CSP 위반 메시지로 차단되는 스크립트와 의존성을 확인하고, 서비스 적용 전에 해당 도구의 수정·대체 가능성을 검토하는 것이 좋습니다. 일정의 근거는 매체가 확인한 Microsoft 메시지 센터 안내이며, 조직별 안내는 Microsoft 365 관리 센터에서 확인할 수 있습니다.
