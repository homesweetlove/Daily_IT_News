### 1. Google Cloud, 장시간 업무를 수행하는 ‘Gemini 에이전트’ 발표

- **핵심 요약:** Google Cloud는 10월 8일 Gemini at Work 행사에서 통합 업무용 Gemini 에이전트를 발표했다. 회사 설명에 따르면 클라우드에서 메모리·문맥을 유지하며 장시간 작업을 수행하고, 임시 하위 에이전트를 만들어 병렬·순차 업무를 조율한다. Workspace 연계와 에이전트별 신원·권한·감사 기록, 프로젝트 지출 한도도 발표 내용에 포함됐다. [공식 발표](https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026)
- **왜 중요한가 / 영향:** 단순 질의응답을 넘어 실제 사내 시스템을 사용하는 업무 자동화 구상이다. **편집부 해석:** 도입 판단에서는 모델 성능뿐 아니라 위임 권한, 실행 기록, 비용 통제가 중요해진다.
- **관찰 포인트:** 발표된 기능이 모두 동일한 일정·계약 조건으로 제공된다고 단정하지 않는다. 실제 도입 시 제공 범위와 권한 정책, 비용 한도 도달 시 동작을 확인할 필요가 있다.

- **핵심 요약:** GlobalFoundries는 10월 8일 TSMC의 CoWoS 첨단 패키징 생태계를 위한 미국 내 실리콘 인터포저 제조 계약을 발표했다. 계약 규모는 20억 달러, 초기 기간은 5년이다. 뉴욕주 몰타 공장 생산능력을 확대하며, 양산 확대는 **2028년 상반기 시작 예정**이다. [공식 발표](https://gf.com/news-and-events/news/globalfoundries-reaches-agreement-to-establish-us-based-supply-of-silicon-interposers-for-advanced-ai-packaging/)
- **왜 중요한가 / 영향:** AI·고성능 컴퓨팅용 첨단 패키징에 필요한 구성요소의 미국 내 공급 기반을 넓히는 계획이다. **편집부 해석:** 공급망 다변화에 의미가 있지만, 오늘 즉시 생산량이 늘거나 전체 패키징 병목이 해소되는 것은 아니다.
- **관찰 포인트:** 몰타 증설 진행과 2028년 양산 확대 일정, 향후 추가 생산능력 확보 여부를 살펴볼 필요가 있다.

## 보안 이슈

### 1. Tensorlake npm SDK 악성 버전 배포…설치 단계에서 자격증명 탈취

- **핵심 요약:** 보안 연구진은 10월 8일 배포된 `tensorlake@0.5.144`에서 자격증명 탈취와 자기전파 악성코드를 확인했다. Socket에 따르면 배포 시각은 01:12:07 UTC(한국시간 10:12:07)다. 설치 스크립트가 허용된 환경에서는 SDK를 실행하거나 불러오기 전에도 악성 코드가 실행될 수 있다. [Socket 분석](https://socket.dev/blog/tensorlake-compromise), [StepSecurity 분석](https://www.stepsecurity.io/blog/tensorlake-npm-compromised-hostage-token-worm)
- **왜 중요한가 / 영향:** 에이전트 실행용 샌드박스와 별개로, SDK를 설치하는 개발자 기기의 비밀정보가 노출될 수 있다. StepSecurity는 정상 저장소·배포 경로에서 만들어진 패키지에 출처 증명(provenance)이 붙어 있었다고 설명했다. **편집부 해석:** 출처 증명만으로 소스 코드의 안전성을 보장할 수는 없다.
- **대응:** 잠금 파일과 설치 이력에서 `0.5.144`를 확인하고 추가 설치를 차단한다. 실행된 호스트는 격리·조사한다. **토큰을 먼저 폐기하지 말고**, 전문가와 함께 `gh-token-monitor` 등 지속성 제거를 확인한 뒤 노출된 토큰·키를 교체한다. 연구진은 모니터가 작동 중일 때 GitHub 토큰을 폐기하면 사용자 파일 삭제가 촉발될 수 있다고 경고했다. StepSecurity는 임시로 `0.5.143` 고정을 권고하지만, 버전 변경만으로 감염이 제거되지는 않는다. [대응 순서](https://www.stepsecurity.io/blog/tensorlake-npm-compromised-hostage-token-worm)
- **확인 수준:** 악성 배포·동작 분석은 복수 연구기관에서 확인돼 신뢰도가 높다. 실제 감염 규모와 공격자 신원은 확정하지 않는다.

### 2. JPCERT/CC, API 악용·정보유출 사례에 새 경보…Metabase도 재점검 권고

- **핵심 요약:** JPCERT/CC는 10월 8일 일본 내 조직의 잇따른 정보유출과 관련해 새 주의보를 발표했다. 내부 API를 통한 권한 변경·계정 생성, 탈취한 API 키 사용에 관한 보고와 Metabase SQL 삽입 취약점 `CVE-2026-72898` 악용 관련 관측을 제시했다. **새 취약점 공개가 아니라 기존 공격 사례를 묶은 신규 경보**다. [10월 8일 주의보](https://www.jpcert.or.jp/at/2026/at260030.html)
- **왜 중요한가 / 영향:** 관리·운영용 API와 BI 도구도 개인정보·업무 데이터 유출 경로가 될 수 있다. Metabase의 해당 결함은 인증 없이 관리자 권한을 얻을 수 있는 문제이며, 벤더는 8월 공지에서 실제 악용을 확인했다. [벤더 보안 공지](https://www.metabase.com/blog/security-update-6-aug-2026)
- **대응:** 외부 노출 API의 인증·권한 검사와 비정상 계정 생성을 점검한다. Metabase는 해당 계열의 최신 보안 버전으로 갱신한다. 최소 수정 버전은 **x.58.24 / x.59.21 / x.60.17 / x.61.11 / x.62.9 / x.63.5**다(`x=0` 오픈소스, `x=1` 상용). 취약 엔드포인트를 외부에 노출했다면 패치만으로 끝내지 말고 모든 활성 사용자 세션을 무효화하고, API 키·관리자 계정·접속 로그를 확인하며 연결 DB 자격증명을 교체한다. [영향 범위·조사 지침](https://www.jpcert.or.jp/at/2026/at260023.html)
- **확인 수준:** 경보 발표와 기관이 보고받은 공격 수법은 공식 자료로 확인된다. JPCERT/CC도 기술 정보가 제한적·단편적이라고 밝혔으므로, 모든 피해를 하나의 원인이나 동일 공격자에게 연결하지 않는다.
