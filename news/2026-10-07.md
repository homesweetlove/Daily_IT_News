## IT 이슈

### 1. Mistral Large 4, API 공개 미리보기 시작…가중치는 월말 공개 예정

- **핵심 요약:** Mistral은 10월 6일 Large 4의 공개 미리보기를 시작했다고 발표했다. Mistral Studio에서 API를 이용할 수 있으며, 모델 가중치는 이달 말 공개할 계획이다. 발표문은 총 약 1조 개, 활성 490억 개 파라미터를 갖춘 멀티모달 모델이라고 설명한다. 현재 API 제공과 향후 가중치 공개를 구분해야 한다. [공식 발표](https://mistral.ai/news/mistral-large-4/) · [공식 변경 기록](https://docs.mistral.ai/resources/changelogs)
- **왜 중요한가 — 편집부 분석:** 기업이 API 시험과 자체 배포 검토를 단계적으로 진행할 수 있는 후보가 추가됐다. 다만 가중치 공개 전에는 자체 운영 가능성·라이선스·하드웨어 요구사항을 실제 배포 기준으로 확정하기 어렵다.
- **관찰 포인트:** 벤치마크 우위에 관한 회사의 홍보성 평가는 이번 요약에서 제외했다. 실제 업무 데이터로 정확도·실패율을 검증하고, 가중치와 상세 기술 자료가 공개되는지 확인할 필요가 있다.

### 2. Meta·Sierra, 개인 AI 에이전트와 기업을 연결할 공통 프로토콜 개발 발표

- **핵심 요약:** Sierra는 10월 6일 Meta와 함께 Personal Agent Protocol을 개발 중이라고 밝혔다. Genesys·Instinct·Rocket·Shopify·Stripe·Walmart가 참여한다. 설계는 OAuth 기반 세션에서 사용자가 읽기·쓰기 접근을 선택하고, 기업이 웹사이트·API·기업 에이전트 중 허용할 연결 경로와 행동을 정하는 방식이다. [Sierra 공식 발표](https://sierra.ai/uk/blog/introducing-personal-agent-protocol)
- **왜 중요한가 — 편집부 분석:** 사용자의 동의와 기업의 권한 정책을 별도로 적용하는 접근이다. 에이전트가 사용자 대신 행동할 때 필요한 신원·권한 경계를 공통화하려는 움직임으로 볼 수 있다.
- **관찰 포인트:** v0.1 명세는 이달 말 공개 예정이며, 상세 권한·알림·결제 확장은 향후 구상이다. 이미 완성·보급된 표준이나 결제 기능으로 해석하면 안 된다. [공식 로드맵](https://sierra.ai/uk/blog/introducing-personal-agent-protocol)

### 3. 영국, 의료 AI 규제 권고 44개 수용…배포 이후 감시 강화 추진

- **핵심 요약:** 영국 정부는 10월 6일 의료 AI 규제 위원회의 44개 권고를 모두 수용한다고 발표했다. MHRA는 AI Airlock 3단계 신청을 열었으며, 이번 단계는 시판 후 감시와 제품 수명주기 규제에 초점을 맞춘다. 변화하는 AI 의료기기 관리에 관한 초안 지침은 2026년 12월, 전체 이행 로드맵은 2027년 봄까지 제시할 계획이다. [영국 정부·MHRA 발표](https://www.gov.uk/government/news/government-backs-recommendations-of-nhs-doctors-led-ai-commission)
- **왜 중요한가 — 편집부 분석:** 의료 AI 개발사의 규제 대응이 출시 전 평가만으로 끝나지 않고, 배포 후 성능 변화와 안전성 관리까지 이어지는 방향을 보여준다.
- **관찰 포인트:** 이번 발표는 권고 수용과 후속 조치 계획이다. 모든 제도가 이미 시행됐거나 국내 규정에도 동일하게 적용되는 것으로 이해해서는 안 된다.

## 보안 이슈

### 1. Django, 보안 취약점 4건 수정…지원 계열 업데이트 권고

- **핵심 요약:** Django는 10월 6일 `6.1.2`, `6.0.9`, `5.2.18`을 보안 릴리스로 배포했다. 지원 중인 6.1·6.0·5.2 계열과 개발 main 브랜치가 대상이다. [Django 공식 보안 발표](https://www.djangoproject.com/weblog/2026/oct/06/security-releases/)

| 취약점 | 핵심 영향 | 공급사 심각도 |
| --- | --- | --- |
| CVE-2026-77050 | 긴 언어 코드의 캐시 누적으로 메모리 과다 사용 가능 | 낮음 |
| CVE-2026-84429 | HTTP 헤더 파싱 비용 증가로 서비스 거부 가능 | 중간 |
| CVE-2026-87890 | 공격자 제어 공간 조회 바이트가 GDAL의 외부 요청 유발 가능 | 중간 |
| CVE-2026-87975 | 편집 가능한 기본키를 쓰는 모델 폼셋에서 조회 범위 밖 객체 삭제·편집 전용 폼셋을 통한 생성 가능 | 중간 |

- **왜 중요한가 — 편집부 분석:** 가용성뿐 아니라 애플리케이션의 권한 경계도 점검해야 하는 업데이트다. 폼셋 문제는 특정 기본키·폼 구성에서 발생하며, 기본 `BigAutoField` 모델은 해당 문제의 영향을 받지 않는다. [영향 조건](https://www.djangoproject.com/weblog/2026/oct/06/security-releases/)
- **대응:** 각 지원 계열을 위 수정 버전으로 업데이트한다. 공간 조회의 래스터 `bytes` 값은 이제 `GDALRaster`로 감싸야 하므로 관련 코드의 호환성도 확인한다. 공식 공지는 실제 공격 발생을 명시하지 않는다. [수정·호환성 안내](https://www.djangoproject.com/weblog/2026/oct/06/security-releases/)

### 2. Firefox 157.0.1, 파일 처리 보호조치 우회 수정

- **핵심 요약:** Mozilla는 10월 6일 MFSA 2026-104를 발표했다. `CVE-2026-106016`은 File Handling 구성요소의 보호조치 우회 문제로, 공급사 심각도는 **중간(Moderate)**이며 `Firefox 157.0.1`에서 수정됐다. [Mozilla 공식 권고](https://www.mozilla.org/en-US/security/advisories/mfsa2026-104/)
- **왜 중요한가 — 편집부 분석:** 브라우저 파일 처리의 보호 기능과 관련된 수정이므로 사용 중인 배포의 패치 상태를 확인할 필요가 있다.
- **대응·확인 한계:** 수정 버전 이상 적용 여부를 점검한다. 공지에는 취약 버전 전체 범위, 상세 공격 조건, 실제 악용 여부가 명시되지 않았다. 원격 코드 실행이나 ‘모든 과거 버전 영향’으로 확대 해석하지 않는다. CVE 기록 공개 시각은 10월 6일 21:30:49 KST다. [Mozilla 제출 CVE 기록](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2026/106xxx/CVE-2026-106016.json)

### 3. Progress 생성기 명령 주입 취약점, CVE 등록·캐나다 권고 새로 공개

- **핵심 요약:** 10월 6일 등록 공개된 `CVE-2026-91140`은 ARCGenAI-Generator `2.0 이상 2.1 미만`의 OS 명령 주입 문제다. 공격자가 조작한 Swagger/OpenAPI 문서를 제공하고 사용자가 생성기를 실행하면, 개발자 환경에서 해당 사용자 권한으로 임의 명령이 실행될 수 있다. 공급사 CVSS 3.1 점수는 **9.6(Critical)**이며 사용자 상호작용이 필요하다. [Progress 제출 CVE 기록](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2026/91xxx/CVE-2026-91140.json)
- **신규성 구분:** 캐나다 사이버보안센터는 10월 6일 AV26-1005를 게시했다. 연결된 공급사 권고 제목에는 ‘September 2026’이 포함돼 있으므로, 이번 이슈는 새 CVE 등록·정부 권고로 다루며 당일 최초 취약점 발견·공개라고 단정하지 않는다. [캐나다 공식 권고](https://www.cyber.gc.ca/en/alerts-advisories/progress-security-advisory-av26-1005)
- **왜 중요한가 — 편집부 분석:** API 설명 문서를 받아 처리하는 개발 도구도 신뢰 경계에 포함해야 한다. 외부 문서를 정상 자료로 취급하는 것만으로 개발 환경의 위험이 사라지지는 않는다.
- **대응:** 공급사 지침대로 `2.1 이상`으로 업데이트하고, 적용 전에는 신뢰하지 않는 Swagger/OpenAPI 문서를 처리하지 않는다. 10월 6일 CVE 기록에 포함된 CISA 평가는 `Exploitation: none`이다. 이는 당시 평가이며, 향후 공격이 없음을 보장하지 않는다. [수정·악용 평가 기록](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2026/91xxx/CVE-2026-91140.json)

**확인 수준:** 보안 항목의 수정 버전·심각도·기술 조건은 공급사 공식 자료 또는 공급사 제출 CVE 기록에 근거한다. 실제 침해 발생은 확인된 사실로 제시하지 않았으며, 상세 조건이 미공개인 항목은 한계를 명시했다.
