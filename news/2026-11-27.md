## IT 이슈

### 1. DeepL, 한국어 포함 6개 언어 음성 번역 모델 Aure v2 제공

**핵심 요약:** DeepL은 26일 Aure v2를 발표하고 DeepL Voice 고객에게 제공한다고 밝혔습니다. 출시 시 지원 언어는 한국어·영어·독일어·프랑스어·스페인어·일본어입니다. 온라인 회의, 대면 대화, 음성 API에서 지원 언어에 자동 적용된다는 설명입니다. [공식 발표](https://www.deepl.com/en/press-release/aure-v2)

**왜 중요한가:** 회사는 음성을 문자로 변환하고 번역한 뒤 다시 음성으로 만드는 단계를 통합해, 음성에서 음성으로 직접 번역하는 구조를 도입했다고 설명했습니다. 번역을 시작할 시점을 학습하는 데 강화학습도 사용했습니다. 회의와 고객 상담에서 번역이 언제 나오느냐는 대화 흐름에 영향을 주는 요소입니다. [공식 발표](https://www.deepl.com/en/press-release/aure-v2)

**수치 해석:** 전작 대비 번역 지연 중앙값이 50% 줄었다는 수치는 DeepL 내부 연구 결과입니다. 시험은 10개 언어 쌍의 1분짜리 실제 발화 녹음을 대상으로, 앱 부가 지연을 제외하고 공개 API를 통해 진행됐습니다. 회사도 실제 대화에서는 결과가 달라질 수 있다고 명시했습니다. 이를 모든 한국어 회의에서 지연이 절반으로 줄어든다는 보장으로 읽어서는 안 됩니다. [시험 조건](https://www.deepl.com/en/press-release/aure-v2)

**관찰 포인트 — 편집부 제안:** 도입을 검토한다면 한국어 전문용어, 여러 사람이 번갈아 말하는 상황, 배경 소음이 있는 통화로 시험하십시오. 응답 속도와 함께 숫자·고유명사·부정 표현의 전달 정확도를 확인할 만합니다.

### 2. Kioxia·NVIDIA, SSD로 GPU의 데이터 접근 공간을 확장하는 실증 공개

**핵심 요약:** Kioxia는 26일 NVIDIA의 SCADA 소프트웨어와 자사 NVMe SSD를 활용한 개념 실증을 발표했습니다. GB200 NVL72 시스템의 18개 서버 노드에 7.68TB XD8 SSD 144개를 구성해 약 1.1PB의 SSD 원시 용량을 마련했습니다. 회사는 이 구조에서 512바이트 벡터 2조 개를 다루는 가능성을 제시했습니다. [공식 발표](https://www.kioxia.com/en-jp/business/news/2026/20261126-1.html)

**왜 중요한가:** 발표의 초점은 HBM만으로 담기 어려운 큰 데이터셋에 GPU가 접근하도록 SSD와 소프트웨어를 결합하는 방법입니다. 회사는 대규모 벡터 데이터베이스와 그래프 신경망 작업을 활용 후보로 들었으며, 기술적 타당성과 성능을 계속 평가하고 있다고 밝혔습니다. [공식 발표](https://www.kioxia.com/en-jp/business/news/2026/20261126-1.html)

**관찰 포인트 — 편집부 해석:** 1.1PB라는 용량과 실제 데이터 처리 속도는 구분해야 합니다. 이번 발표는 실증 구성과 처리 가능성을 설명한 것으로, HBM에 준하는 접근 속도나 범용 애플리케이션의 성능 향상률을 판단할 자료는 추가로 필요합니다. 운영 적용 여부는 실제 작업의 지연시간·처리량·비용 결과를 확인한 뒤 검토하는 편이 좋습니다. [실증 범위](https://www.kioxia.com/en-jp/business/news/2026/20261126-1.html)

## 보안 이슈

### 1. Drupal 설치 프로그램 추가 취약점…앞선 패치 적용 사이트도 재확인 필요

**핵심 요약:** SecurityWeek는 26일 Drupal 설치 프로그램의 추가 취약점 `CVE-2026-136716`을 보도했습니다. 근거인 공식 권고 SA-CORE-2026-019는 25일 공개됐습니다. Drupal은 앞선 SA-CORE-2026-017 수정 이후에도 특수하거나 불완전한 설치 상태의 일부 운영 사이트가 탈취될 수 있으며, **실제 악용이 진행 중**이라고 경고했습니다. [26일 보도](https://www.securityweek.com/drupal-installer-patch-left-a-gap-attackers-are-already-exploiting/), [공식 권고](https://www.drupal.org/sa-core-2026-019)

**왜 중요한가:** 기존 패치를 설치했다는 사실만으로 이번 문제의 조치가 끝났다고 볼 수 없습니다. 공식 권고에 따르면 취약한 상태는 화면에서 분명히 드러나지 않을 수 있고, 이미 침해된 사이트는 더 이상 같은 취약 상태를 보이지 않을 수도 있습니다. 설치 프로그램을 이미 안전하게 보호한 사이트는 이번 취약점의 영향을 받지 않는다고 설명했습니다. [공식 권고](https://www.drupal.org/sa-core-2026-019)

**대응 포인트:** 지원 중인 계열별 수정 버전은 다음과 같습니다. 해당 상태의 기존 운영 사이트를 수정하려면 새 버전 설치 후 **`update.php`를 실행해 업데이트 훅까지 적용**해야 합니다. 모든 신규·기존 사이트에서 설치 프로그램 보호 지침을 따르는 것도 강하게 권고됐습니다. [공식 조치 안내](https://www.drupal.org/sa-core-2026-019)

| 운영 계열 | 공식 권고의 수정 버전 |
| --- | --- |
| Drupal 11.4.x | 11.4.14 |
| Drupal 11.3.x | 11.3.23 |
| Drupal 10.6.x | 10.6.23 |

**침해 점검:** Drupal은 로그에서 무단 접근과 `user 1` 계정의 예상치 못한 변경을 살피고, 해당 계정의 이메일이 자신이 통제하는 주소인지 확인하며 비밀번호 재설정을 검토하라고 안내했습니다. **편집부 제안:** 이번 CVE와 앞선 설치 프로그램 취약점을 자산 관리에서 구분해 추적하고, 패치 완료 여부와 침해 조사 결과를 함께 기록하십시오. [공식 권고](https://www.drupal.org/sa-core-2026-019)

### 2. 1Password 직원 GitHub 계정 침해로 고객 계정 정보 복사…회사 “금고 내용은 미영향”

**핵심 요약:** 26일 보도된 1Password 사건은 회사가 25일 공개한 조사 결과에 관한 것입니다. 회사는 19일부터 직원의 업무용 GitHub 계정에 대한 무단 접근 정황을 조사했으며, 공격자가 소스 코드를 열람하고 백엔드 서비스에 악성 코드를 넣어 일부 고객의 관리용 계정 정보를 내려받았다고 밝혔습니다. [26일 보도](https://securityaffairs.com/204031/cyber-crime/1password-hacked-customer-names-and-emails-copied-vaults-untouched.html), [회사 공지](https://1password.com/blog/update-on-nov-2026-security-incident)

**영향 범위:** 회사가 열거한 정보에는 이름·이메일, 계정·사용자 식별자, 계정 생성 및 마지막 로그인 시각, 일부 초대·프로비저닝·복구 이메일 링크의 토큰 등이 포함됩니다. 회사는 고객 금고 내용과 보호 키, 계정 복구 키는 영향을 받지 않았다고 설명했습니다. 이는 현재 공개된 회사의 조사 설명이며, 피해 고객 수는 이번 공개 자료에서 확인되지 않습니다. [회사 공지](https://1password.com/blog/update-on-nov-2026-security-incident), [후속 보도](https://securityaffairs.com/204031/cyber-crime/1password-hacked-customer-names-and-emails-copied-vaults-untouched.html)

**대응 현황과 의미:** 회사에 따르면 이메일 링크 토큰만으로 계정에 접근할 수는 없으며 SSO 로그인 또는 이메일 코드가 추가로 필요합니다. 회사는 관련 코드를 6자리 숫자에서 10자리 영숫자로 늘리고, 영향받은 GitHub 계정을 비활성화했으며, 노출 가능성이 있는 내부 자격 증명을 교체·폐기했습니다. 노출된 프로비저닝 토큰을 사용한 계정 탈취의 내부 증거는 확인하지 못했다고 밝혔습니다. [회사 공지](https://1password.com/blog/update-on-nov-2026-security-incident)

**사용자 대응:** 회사는 예기치 않은 초대·복구 이메일이나 문자·전화 형태의 피싱에 주의하라고 권고했습니다. 비밀번호와 Secret Key는 직접 연 공식 앱이나 직접 주소를 입력한 공식 웹사이트에서만 입력하라는 안내입니다. **편집부 제안:** 금고 내용에 대한 회사 설명과 계정 메타데이터 노출 위험을 구분하고, 시작하지 않은 복구 요청은 특히 주의해서 확인하십시오. [회사 권고](https://1password.com/blog/update-on-nov-2026-security-incident)
