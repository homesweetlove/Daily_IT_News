### 1. Akamai, Anthropic과 116억 달러 규모의 7년 클라우드 계약

**핵심 요약**  
Akamai는 Anthropic에 클라우드 인프라를 공급하는 7년 계약을 체결했습니다. 초기 계약 가치는 116억 달러이며, Anthropic은 조건에 따라 Akamai 지분을 최대 5%까지 확보할 수 있는 워런트를 받습니다. Akamai는 초기 계약 이행을 위해 약 55억 달러의 자본 지출을 예상하고 있습니다.

**왜 중요한가**  
생성형 AI 기업이 필요한 연산 용량을 확보하기 위해 공급처를 다변화하고 있음을 보여줍니다. 동시에 대규모 장기 계약과 지분 연계 구조가 클라우드 사업자와 AI 모델 기업의 이해관계를 더욱 밀접하게 만들고 있습니다. 메모리와 서버 부품의 선구매도 늘어날 수 있어 공급망 가격과 가용성에 파급될 가능성이 있습니다.

**대응·관찰 포인트**

- Anthropic의 실제 사용량과 추가 계약 확대 여부
- Akamai의 설비 투자 증가가 현금흐름과 기존 CDN·보안 사업에 미치는 영향
- GPU뿐 아니라 메모리·전력·네트워크 장비까지 이어지는 공급 제약

### 2. Oracle ‘Project Jupiter’, 전력 공급 지연 가능성으로 불가항력 통지

**핵심 요약**  
Oracle은 뉴멕시코에서 추진 중인 대형 데이터센터 ‘Project Jupiter’와 관련해 전력 공급 지연 가능성을 이유로 Blue Owl 측에 불가항력 통지를 보냈습니다. Oracle은 현재 프로젝트가 계획된 일정대로 진행되고 있다는 입장이며, 시설은 2028년 가동을 목표로 하는 것으로 전해졌습니다.

**왜 중요한가**  
AI 데이터센터 확대의 실질적인 제약이 반도체 확보를 넘어 송전망, 발전원, 가스관, 용수, 환경 인허가와 금융 구조로 이동하고 있습니다. 대규모 단일 프로젝트의 지연은 AI 서비스 공급 일정과 장기 클라우드 계약의 비용 구조에도 영향을 줄 수 있습니다.

**대응·관찰 포인트**

- 전력 공급 일정과 추가 인허가 진행 상황
- 프로젝트 지연 시 발생할 수 있는 금융비용 및 계약 책임
- 신규 데이터센터 입지 선정에서 전력망 접근성과 지역사회 수용성의 비중 확대

## 보안 이슈

### 1. TeamCity CVE-2026-63077, 실제 공격과 랜섬웨어 악용 보고

**핵심 요약**  
JetBrains TeamCity On-Prem의 인증 우회 취약점 CVE-2026-63077이 실제 공격에 악용되고 있으며, CISA가 랜섬웨어 캠페인 관련 표시를 갱신했다고 보도됐습니다. 공격자는 인증 없이 에이전트 폴링 프로토콜을 악용해 TeamCity 서버 권한으로 운영체제 명령을 실행할 수 있습니다.

**영향**  
빌드 서버의 소스 코드, 설정, 저장된 자격 증명이 노출될 수 있고, 빌드 산출물이나 하위 CI/CD 배포 체인이 변조될 수 있습니다. 개발망에서 높은 권한을 가진 TeamCity 특성상 단일 서버 침해가 공급망 공격으로 확장될 위험이 큽니다.

**대응**

- TeamCity On-Prem을 2025.11.7 또는 2026.1.3 이상으로 즉시 업데이트
- 즉시 업그레이드할 수 없다면 JetBrains가 제공하는 보안 패치 플러그인 적용
- 외부 접근을 신뢰 네트워크나 VPN으로 제한하고 TeamCity 서비스 계정 권한 최소화
- 로그에서 XStream 변환 예외, 비인가 에이전트, 이름이 ‘scan’으로 시작하는 예상 밖 에이전트 점검
- TeamCity Cloud 사용자는 별도 조치가 필요하지 않음

[JetBrains 공식 권고](https://blog.jetbrains.com/teamcity/2026/08/cve-2026-63077-update/) · [관련 보도](https://www.bleepingcomputer.com/news/security/cisa-ransomware-gangs-now-exploiting-critical-teamcity-flaw/)

### 2. Roundcube CVE-2026-48842, 사전 인증 SQL 인젝션 실제 악용

**핵심 요약**  
Roundcube의 virtuser_query 플러그인에 존재하는 CVE-2026-48842가 실제 공격에 악용되고 있다고 캐나다 사이버보안센터가 경고했습니다. 공격에는 인증이나 사용자 상호작용이 필요하지 않으며, 취약점 악용 시 인증 우회, 악성 데이터베이스 명령 실행, 데이터 탈취가 가능할 수 있습니다.

**영향**  
웹메일은 계정 복구 메일, 내부 대화, 첨부파일과 주소록이 모이는 핵심 시스템입니다. 공개 인터넷에서 접근 가능한 Roundcube 서버가 많아 패치되지 않은 조직은 초기 침투와 계정 탈취 위험에 노출됩니다.

**대응**

- Roundcube 1.6.16 또는 1.7.1 이상으로 즉시 업데이트
- 패치가 어려우면 virtuser_query 플러그인을 비활성화하거나 제거
- 웹·데이터베이스 로그에서 비정상 쿼리와 인증 우회 흔적 확인
- 노출된 관리자·메일 계정 자격 증명과 세션 토큰 교체 검토

[캐나다 사이버보안센터 권고](https://www.cyber.gc.ca/en/alerts-advisories/roundcube-security-advisory-av26-503) · [Roundcube 보안 업데이트](https://roundcube.net/news/2026/05/24/security-updates-1.6.16-and-1.7.1) · [관련 보도](https://www.bleepingcomputer.com/news/security/critical-roundcube-flaw-now-actively-exploited-in-code-injection-attacks/)

### 3. 공개된 GitLab 프로젝트 이메일, 권한 대행 통로로 악용 가능

**핵심 요약**  
GitLab의 ‘이메일로 프로젝트 작업 항목 생성’ 기능은 사용자별 비공개 이메일 주소를 발급합니다. 이 주소를 아는 사람은 주소 소유자인 것처럼 이슈나 병합 요청을 생성할 수 있습니다. 일부 프로젝트가 버그 제보 편의를 위해 해당 주소를 공개 README·지원 문서에 게시한 사례가 발견됐습니다.

**영향**  
노출된 주소의 소유자가 높은 권한을 보유하면 공격자가 병합 요청 생성, CI/CD 실행 유도, 비공개 프로젝트 정보 접근 등으로 공격을 확장할 수 있습니다. GitLab 공식 문서도 이 주소를 비밀로 유지하고 유출 시 토큰을 재설정하라고 안내합니다.

**대응**

- 공개 저장소, 문서, 위키, 이슈에서 프로젝트 전용 이메일 주소 검색·삭제
- 주소가 한 번이라도 공개됐다면 GitLab에서 이메일 토큰 재설정
- 봇·공용 계정에 최소 권한 적용하고 외부 기여자의 파이프라인 자동 실행 제한
- 감사 로그에서 이메일로 생성된 예상 밖의 이슈·병합 요청 확인

[GitLab 공식 문서](https://docs.gitlab.com/user/project/issues/create_issues/) · [Aikido 분석](https://aikido.dev/blog/gitlab-email-push-to-main) · [관련 보도](https://www.bleepingcomputer.com/news/security/exposed-gitlab-project-email-addresses-let-attackers-push-code/)

### 4. Carbonato, 노출된 Docker를 장악해 AI 에이전트를 사후 침투에 활용

**핵심 요약**  
Carbonato 캠페인은 인증 없이 인터넷에 노출된 Docker API의 기본 포트 2375를 찾아 권한이 높은 컨테이너를 실행합니다. 이후 호스트 파일시스템과 프로세스에 접근하고, 역방향 SSH 터널·SSH 키·cron 또는 systemd 등을 이용해 지속성을 확보합니다. 공격자는 Hermes Agent를 설치한 뒤 AI API 키, SSH 자격 증명과 접근 토큰 수집 같은 사후 침투 작업을 지시합니다.

**영향**  
자동화 스크립트가 전파와 지속성을 담당하고 AI 에이전트가 운영자의 사후 작업을 보조하는 혼합형 공격입니다. 감염 호스트가 연결된 /24 네트워크를 반복 스캔해 추가 Docker 데몬을 찾기 때문에 한 대의 잘못된 공개 설정이 내부 확산으로 이어질 수 있습니다.

**대응**

- Docker 데몬 API를 인터넷에 노출하지 말고, 필요한 경우 상호 TLS와 방화벽·VPN으로 제한
- 컨테이너 레지스트리에 인증을 강제하고 특권 컨테이너 실행을 제한
- 예상 밖의 2375 포트 접근, 역방향 SSH, Telegram 통신, CARBONATO_API_KEY 환경변수와 GH0ST 문자열 점검
- 노출 가능성이 있는 AI API 키, SSH 키와 접근 토큰을 즉시 폐기·재발급

[ThreatDown 기술 분석](https://www.threatdown.com/blog/carbonato/) · [관련 보도](https://www.bleepingcomputer.com/news/security/new-carbonato-malware-uses-ai-agents-to-hijack-exposed-docker-hosts/)
