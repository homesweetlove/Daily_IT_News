### 2. [Check Point VPN·관리 서버 취약점 2건 실제 악용](https://blog.checkpoint.com/security/security-advisory-action-required-active-exploitation-of-cve-2026-85102-and-a-management-pre-authentication-vulnerability-cve-2026-93616/)

**핵심 요약**

Check Point는 인증 전 원격 코드 실행 취약점 CVE-2026-85102와 인증 전 경로 탐색 취약점 CVE-2026-93616이 실제 공격에 악용되고 있다고 확인했습니다. 두 취약점 모두 CVSS 9.8입니다. 전자는 Security Gateway의 VPN 인증서 처리 과정에서 원격 코드 실행을 허용하며 9월 12일부터 Spark 고객을 겨냥한 공격이 관찰됐습니다. 후자는 Security Management 웹 서비스에서 임의 경로의 스크립트 실행과 Java 클래스 로드를 허용하며 제한적인 표적 공격이 확인됐습니다.

**왜 중요한가**

인터넷에 노출되는 VPN 게이트웨이와 중앙 관리 서버는 내부망 진입과 보안 정책 장악으로 이어질 수 있는 고가치 표적입니다. CISA도 두 취약점을 Known Exploited Vulnerabilities 목록에 추가했으며, 미국 연방기관의 조치 기한은 9월 25일입니다.

**대응·관찰 포인트**

- Check Point 권고에 따라 CVE-2026-85102용 LivePatch Take 26 또는 지원 버전의 수정 Jumbo Hotfix를 즉시 적용하고 Spark 방화벽도 수정 빌드 이상으로 올려야 합니다.
- 이전 오프라인 LivePatch 설치만으로는 완전한 보호가 되지 않을 수 있으므로 실제 활성 버전을 검증해야 합니다.
- CVE-2026-93616은 별도 보안 공지의 수정본과 침해지표를 적용하고, 인증서 기반 비정상 로그인과 후속 내부 스캔을 점검해야 합니다.

### 3. [WordPress 핵심 취약점 CVE-2026-87902, 패치 직후 공격으로 확대](https://github.com/WordPress/wordpress-develop/security/advisories/GHSA-7hp8-65ch-5whp)

**핵심 요약**

WordPress의 페이지 템플릿 해석 과정에 존재하는 인증 없는 경로 탐색 취약점 CVE-2026-87902가 실제 공격에 악용되고 있습니다. CVSS 9.2의 이 취약점은 특정 테마·서버 조건이 맞으면 웹 서버가 읽을 수 있는 로컬 PHP 파일을 포함시켜 원격 코드 실행으로 이어질 수 있습니다. 보안업체 Patchstack은 패치 공개 5시간 이내에 탐색이 시작됐고 이후 트래픽이 10배 늘었으며, 공격자가 디스크에 명령 실행용 PHP 파일을 쓰는 단계까지 진행됐다고 보고했습니다.

**왜 중요한가**

WordPress 핵심 구성요소의 문제라 특정 플러그인 사용자에 국한되지 않으며, 공개 패치 분석 뒤 실제 공격으로 전환되는 시간이 매우 짧았습니다. 공식 PHP Docker 이미지와 PHP 8.5 미만을 사용하는 기본 cPanel 구성도 조건에 따라 영향을 받을 수 있습니다.

**대응·관찰 포인트**

- WordPress 7.1.2 또는 각 유지보수 브랜치의 수정 버전으로 즉시 업데이트해야 합니다. 수정은 4.7 계열까지 백포트됐습니다.
- 웹 접근 로그에서 이중 인코딩된 경로 탐색과 pagename 요청을 확인하고, /tmp·/var/tmp의 의심스러운 PHP 파일과 비정상 명령 실행 흔적을 조사해야 합니다.
- 알려진 IP 차단만으로는 충분하지 않으므로 패치와 서버 측 탐지를 우선해야 합니다.

### 4. [Arista VeloCloud Orchestrator 제로데이 CVE-2026-93952 실제 악용](https://www.arista.com/en/support/advisories-notices/security-advisory/24765-security-advisory-0183)

**핵심 요약**

Arista는 VeloCloud Orchestrator(VCO) 온프레미스의 부적절한 입력 검증 취약점 CVE-2026-93952가 실제 공격에 악용 중이라고 밝혔습니다. CVSS v3.1 기준 10.0으로, 인증서 기반 Edge–Orchestrator 인증을 사용하는 환경에서 공격자가 VCO 웹 인터페이스에 접근하고 Edge 인증서의 공개 부분을 확보하면 계정 자격 증명 없이 내부 특권 기능에 접근할 수 있습니다. 호스팅형 서비스는 이미 패치됐지만 일부 온프레미스 버전은 수정 릴리스 적용이 필요합니다.

**왜 중요한가**

VCO는 SD-WAN과 엣지 장비를 중앙에서 관리하므로 침해 시 Orchestrator의 기밀성·무결성·가용성뿐 아니라 관리 대상 장비와 인증정보까지 영향이 확산될 수 있습니다. CISA도 이 취약점을 악용 확인 목록에 추가했습니다.

**대응·관찰 포인트**

- 수정된 VCO 5.2.3.16 이상 또는 6.4.2.8 이상으로 업그레이드하고, 다른 지원 브랜치는 Arista의 후속 수정 릴리스를 확인해야 합니다.
- 패치 전에는 VCO 웹 인터페이스를 신뢰할 수 있는 관리망으로 제한하고, 비정상 URL·인코딩 문자·내부 서비스 참조·과도한 요청을 점검해야 합니다.
- x-vc-opt HTTP 헤더, 비정상 외부 연결, 예상치 못한 파일·서비스 생성 흔적이 있으면 로그와 파일시스템 시간을 보존한 뒤 사고 대응과 자격 증명 교체를 진행해야 합니다.
