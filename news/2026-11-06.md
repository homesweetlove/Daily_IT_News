## IT 이슈

### 1. Dropbox, Tigris 인수 계약과 DBX Agent Cloud 발표…AI 데이터 인프라로 확장

**새 소식:** Dropbox는 11월 5일 분산 객체 스토리지 기업 Tigris Data 인수 계획을 발표했습니다. 8-K 공시에 따르면 계약 체결일은 **11월 3일**, 대가는 통상적인 가격 조정을 전제로 **현금 약 3억 5,000만 달러**입니다. 종결은 일반적인 거래 조건의 충족 또는 면제를 전제로 2026년 4분기에 예상합니다. [Dropbox 발표][1], [8-K 공시][2]

**핵심 내용:** 함께 공개한 **DBX Agent Cloud**는 S3 호환 객체 스토리지부터 제공하는 개발자용 저장·데이터 인프라입니다. 파일시스템과 콘텐츠 처리 기능은 다음 단계의 계획으로 설명했습니다. 기존 Dropbox 제품에 들어가는 AI 기능의 초기 배포는 미국·영국·호주의 적격 Standard·Advanced 팀과 영어를 중심으로 진행되며, 더 넓은 제공 범위는 2027년 계획입니다. 이 이용 조건을 DBX Agent Cloud 전체의 출시 조건과 혼동하지 않아야 합니다. [공식 발표][1]

**왜 중요한가 / 관찰 포인트 — 편집부 분석:** 파일 협업 서비스 기업이 AI 앱의 데이터 저장 계층으로 사업 범위를 넓히는 움직임입니다. 기업 도입 검토에서는 인수 종결 여부와 별개로 객체 스토리지의 실제 제공 지역·요금·접근 권한·이전 조건을 확인할 필요가 있습니다.

### 2. Ripple-65B Preview 공개 보도…Apache 2.0 가중치와 배포 형태 확인

**새 소식:** VentureBeat가 11월 5일 보도했습니다. [보도][5] Ricursive의 공식 발표는 자사 칩 설계 플랫폼을 구동하는 독점 모델에서 파생된 **범용 모델**을 공개한다고 설명합니다. 공개 대상은 해당 칩 설계 플랫폼 전체가 아닙니다. [Ricursive 발표][3]

**핵심 내용:** 공식 모델 카드는 **650억 파라미터 밀집형 Transformer**와 최대 **100만 토큰 문맥 길이** 지원을 설명합니다. 공개 구성에는 BF16·NVFP4 지시 학습 모델과 BF16 기본 모델이 있으며, Apache 2.0 라이선스가 표시돼 있습니다. 이는 모델 설명의 지원 범위이며 외부 API 서비스가 동일한 문맥 길이를 제공한다는 의미는 아닙니다. [공식 모델 카드][4]

**왜 중요한가 / 관찰 포인트:** 모델 카드는 자체 평가와 공개 수치를 혼합했으며 에이전트 평가의 재현이 어렵다고 명시합니다. **편집부 분석:** 자체 호스팅 후보를 평가할 때는 가중치 형식별 메모리 사용량과 실제 저장소 작업의 성공률을 측정해야 합니다. 회사의 비교 벤치마크 순위를 모든 개발 환경의 성능 보장으로 해석하기는 어렵습니다. [평가 방법 설명][4]

## 보안 이슈

### 1. OpenSSH 10.6p2 긴급 공개…Alpine의 특정 비밀번호 인증 설정 점검 필요

**새 소식:** OpenSSH는 11월 5일 **10.6p2**를 공개했습니다. 릴리스 노트는 musl libc를 사용하는 Linux에서 PAM을 비활성화한 일부 환경의 비밀번호 인증 우회를 차단하는 긴급 조치를 포함한다고 설명합니다. [OpenSSH 공식 릴리스 노트][6]

**영향 조건:** Alpine 권고는 다음 조건이 모두 맞는 경우를 제시합니다. 공지 작성 시점에는 CVE 식별자가 부여되지 않았습니다. [Alpine 공식 권고][7]

- PAM 없는 `openssh-server`, 또는 `UsePAM no`인 `openssh-server-pam`을 사용한다.
- `PasswordAuthentication yes`가 적용돼 있다.
- 비밀번호 필드가 `*`인 계정이 있다.
- 다른 로컬 계정 중 하나 이상에 `$5$` 또는 `$6$` 형식의 비밀번호 해시가 있다.

**대응:** Alpine은 수정 패키지 설치 후 **sshd 재시작**을 요구합니다. 대표 브랜치의 수정 버전은 아래와 같으며, 상위 OpenSSH 버전 번호만으로 배포판의 패치 적용 여부를 판단하지 않아야 합니다. [Alpine 수정 패키지 표][7]

| Alpine 브랜치 | 수정된 openssh 패키지 |
|---|---|
| 3.24 | 10.3_p1-r2 |
| 3.23 | 10.2_p1-r1 |
| 3.22 | 10.0_p1-r11 |
| edge | 10.6_p2-r0 |

즉시 갱신할 수 없다면 `PasswordAuthentication no`로 비밀번호 로그인을 끄는 방법을 안내합니다. 먼저 키 로그인이 되는지 확인하고, 새 연결 검증 전에는 기존 세션을 유지해야 합니다. sshd를 실행하지 않는 컨테이너와 PAM 인증을 사용하는 구성 등은 이 영향 조건과 구분됩니다. **편집부 분석:** ‘키로만 접속하는 계정’이 있다는 사실보다 서버의 실제 인증 설정을 확인하는 것이 중요합니다. [Alpine 대응·영향 제외 조건][7]

### 2. Zyxel GS1900 후속 보도, 기존 Patch 2의 보호 범위 재점검 촉구

**새 소식과 시간 구분:** The Hacker News는 11월 5일 Binarly의 분석을 인용해 GS1900의 기존 **2.90 Patch 2**가 해당 공격 경로를 차단하지 못한다고 보도했습니다. 새 문제는 **CVE-2026-107441**, 종전 권고의 문제는 **CVE-2026-7273**으로 구분됩니다. Zyxel의 새 공식 권고 게시일은 **11월 3일**이므로 오늘 처음 배포된 수정본으로 다루지는 않습니다. [후속 보도][9], [Zyxel 공식 권고][8]

**핵심 내용과 영향:** 제조사는 GS1900 펌웨어의 CGI 프로그램에서 경계 밖 메모리 쓰기가 발생해, LAN에서 접근 가능한 비인증 공격자가 조작한 HTTP 요청으로 운영체제 명령을 실행할 수 있다고 설명합니다. 공식 표의 해당 10종은 Patch 2 이하가 영향 범위이며, 모델별 **2.90 Patch 3** 빌드가 수정본입니다. [Zyxel 공식 권고][8]

**대응:** 예를 들어 GS1900-8은 **2.90(AAHH.3)C0**, GS1900-24는 **2.90(AAHL.3)C0**, GS1900-48은 **2.90(AAHN.3)C0**가 수정본입니다. 다른 모델은 공식 표에서 모델명과 빌드 코드를 직접 대조해야 합니다. [제조사 전체 모델·펌웨어 표][8]

**왜 중요한가 / 관찰 포인트:** 보도는 과거 실제 공격을 받은 장비들이 Patch 2를 설치한 상태였는지는 확인되지 않았다고 구분합니다. 따라서 연구진의 재현 결과를 ‘이미 패치한 모든 장비의 침해 확인’으로 확대할 수는 없습니다. **편집부 분석:** 새 펌웨어 적용과 함께 관리 인터페이스의 접근 경로를 점검하고, 침해가 의심되는 장비는 업데이트 완료와 사고 조사 완료를 별도로 판단해야 합니다. [보도의 확인 범위][9]
