## IT 이슈

### 1. Inkling 2 Small, Tinker에서 제공 시작…가중치 공개는 다음 단계

**핵심 요약:** Thinking Machines는 미국 현지 11월 5일 Inkling 2 Small을 발표했습니다. 11월 6일 보도는 공식 발표 게시물의 시각을 5일 23:43 UTC, 한국 시각 6일 08:43으로 전해 이번 조사 범위에 들어옵니다. 모델은 전체 5,940억 개 가운데 토큰 처리 시 170억 개 파라미터를 활성화하는 MoE 구조입니다. 텍스트·이미지를 입력받아 텍스트를 출력하며, Tinker에서 추론과 미세조정을 제공합니다. [1] [2] [3]

**왜 중요한가:** 이번 발표에서 현재 가능한 것은 Tinker를 통한 이용입니다. 회사는 외부 안전성 시험과 레드팀 검증 후 다음 주에 전체 가중치를 Apache 2.0으로 공개하겠다고 밝혔지만, 현재 배포는 비공개 가중치 방식이며 모델 카드도 Tinker 이용약관을 안내합니다. 자체 서버 도입을 검토할 때 이 두 단계를 구분해야 합니다. [1] [2]

**관찰 포인트 — 편집부 분석:** 실제 가중치와 라이선스 파일이 게시되는지 확인한 뒤 자체 운영 가능성을 판단할 필요가 있습니다. 파라미터 수나 공급자 벤치마크만으로 도입을 결정하기보다, 한국어 업무 정확도·응답 지연·운영 비용을 실제 사용 조건에서 비교하는 편이 좋습니다.

### 2. EU, TikTok 추천의 ‘토끼굴 효과’에 DSA 위반 예비 판단

**핵심 요약:** EU 집행위원회는 11월 6일 TikTok의 ‘For You’ 추천 시스템이 디지털서비스법(DSA)을 위반했다는 예비 판단을 발표했습니다. 시청·좋아요 같은 반응을 바탕으로 비슷한 영상을 계속 추천하면서 정신건강이나 신체 이미지와 관련된 콘텐츠에 이용자를 반복적으로 노출시키는 위험을 문제 삼았습니다. 위원회는 위험 평가와 완화 조치 모두 충분하지 않았다고 봤습니다. [4]

**왜 중요한가:** 위원회는 콘텐츠 다양화와 ‘관심 없음’ 도구가 반복 노출을 충분히 줄이지 못한다고 판단했습니다. 특히 시청 시간이 이용자의 명시적 거부 의사보다 추천에 더 큰 영향을 줄 수 있다는 점을 지적하고, 명시적 선호 반영·이용자 제어 개선·정기적인 알고리즘 시험 등을 요구했습니다. 추천 시스템의 설계 자체가 심사 대상이라는 점이 핵심입니다. [4]

**관찰 포인트:** 이는 최종 위반 확정이나 과징금 부과 결정이 아닙니다. TikTok은 조사 자료를 검토하고 서면으로 반박할 수 있으며, 위원회도 이번 판단이 조사 결과를 미리 확정하는 것은 아니라고 명시했습니다. [4]

## 보안 이슈

### 1. Chainalysis, 거래 모니터링 서비스부터 단계적 복구

**핵심 요약 — 이번에 달라진 점:** Chainalysis는 11월 6일 03:30 EST, 한국 시각 17:30 공지에서 KYT와 Address Screening의 접속 복구를 단계적으로 시작했다고 밝혔습니다. Reactor와 Data Solutions는 보안 강화와 복구 작업이 계속 진행 중입니다. 따라서 모든 제품이 정상화됐다고 볼 수는 없습니다. [5]

**배경과 영향:** 앞선 11월 4일 공지에서는 전체 사용자의 이름·사용자명·비밀번호 해시·유효 토큰이 공격자에게 노출됐다고 확인했습니다. 이를 모든 사용자의 평문 비밀번호 유출로 해석해서는 안 됩니다. 회사는 당시 조사에서 수사 데이터 접근이나 블록체인 귀속 데이터 조작의 증거를 찾지 못했다고 설명했으며, 조사는 진행 중입니다. [5]

**필요한 대응:** 이용 조직은 기존 공식 지원 채널이나 담당자를 통해 허용 목록에 넣을 신뢰 IP를 제출해야 합니다. 접속이 복구되면 거래 등록 전에 모든 사용자의 비밀번호를 재설정하고, 해당되는 API 키도 교체해야 합니다. 다른 서비스에서 같은 비밀번호를 썼다면 그 비밀번호도 변경하라는 것이 회사의 안내입니다. [5]

**편집부 분석:** 복구 여부와 인증정보 교체 여부를 별도로 확인하고, API 연동이 실제로 다시 작동하는지 점검해야 업무 재개 상태를 판단할 수 있습니다.

### 2. OpenSSH ‘SSHole’, 패치 발표 뒤 공격 시도 관측

**핵심 요약 — 이번에 달라진 점:** Previdian은 CVE-2026-123158을 겨냥한 센서 관측을 공개하고 최초 관측일을 11월 6일로 표시했습니다. 같은 날 The Hacker News는 이 회사가 CVE 공개 후 9시간이 지나기 전에 공격 시도를 포착했으며, Alpine Linux·OpenSSH 실험용 허니팟에서 root 접근 성공도 확인했다고 보도했습니다. 센서의 공격 시도 확인과 일반 운영 서버의 침해 확인은 구분해야 합니다. [6] [7]

**영향 범위:** 전날 패치가 발표된 이 문제는 musl 기반 Linux에서 PAM 없이 동작하는 OpenSSH의 특정 비밀번호 인증 구성에 해당합니다. Alpine 권고에 따르면 비밀번호 인증 허용, 비밀번호 필드가 `*`인 계정, 다른 계정의 `$5$` 또는 `$6$` 해시 존재 등 조건이 함께 충족돼야 합니다. 정상적인 비밀번호 해시를 가진 모든 계정의 인증을 무조건 우회하는 결함은 아닙니다. [7] [8]

**필요한 대응:** Alpine은 사용하는 배포판 분기에 맞는 수정 패키지를 설치한 뒤 `sshd`를 재시작하라고 권고합니다. 예를 들어 Alpine 3.24의 수정 패키지는 `10.3_p1-r2`, 3.23은 `10.2_p1-r1`이므로 버전 문자열이 10.6p2보다 작다는 이유만으로 미수정 상태라고 판단해서는 안 됩니다. 당장 업데이트할 수 없다면 키 로그인이 되는지 먼저 확인하고 현재 세션을 유지한 상태에서 비밀번호 인증을 끄는 임시 조치를 검토해야 합니다. [8]

**관찰 포인트 — 편집부 분석:** 인터넷에 노출된 해당 SSH 서버부터 설정과 패치 적용 여부를 확인할 필요가 있습니다. 허니팟의 root 접근 사례만으로 모든 영향 시스템에서 root 권한 탈취가 가능하거나 대규모 피해가 발생했다고 단정할 수는 없습니다.
