### 1. 미국·중국, AI 사고 연락 채널과 위험·편익 대화에 합의

**핵심 요약**  
미국과 중국은 정상회담 후 AI 기술의 위험과 편익을 논의하는 대화를 시작하고, AI 관련 사고가 발생했을 때 소통할 채널을 구축하기로 했습니다. 다음 협의는 11월로 예정됐습니다. 양국은 별도로 상호 300억 달러 규모의 비민감 품목에 대한 관세 인하에도 합의했습니다.

**왜 중요한가**  
AI 안전 문제를 세계 양대 기술 강국 간의 공식 외교 의제로 다루기 시작했다는 점이 핵심입니다. 모델 오작동, 사이버 사고, 군사적 오인처럼 국경을 넘는 사건에 최소한의 연락 체계가 생기면 급격한 긴장 고조를 줄일 수 있습니다. 다만 구체적인 통보 기준, 공유할 기술 정보와 검증 절차는 아직 공개되지 않았습니다.

**관찰 포인트**

- 11월 협의에서 합의될 ‘AI 사고’의 범위와 통보 시간
- 민감한 모델·컴퓨팅 정보의 공유 수준과 검증 방식
- 수출 통제와 AI 안전 협력이 동시에 진행될 수 있는지 여부

### 2. Apple, 햅틱 특허 소송에서 57억 달러 이상 배상 평결

**핵심 요약**  
미국 배심원단은 iPhone과 Apple Watch의 진동 피드백을 구현하는 Taptic Engine이 Taction의 특허 2건을 침해했다고 판단하고, Apple이 57억 달러 이상을 배상해야 한다고 평결했습니다. Taction은 2021년 소송을 제기했으며, Apple은 자사 기술이 근본적으로 다르다며 항소하겠다고 밝혔습니다.

**왜 중요한가**  
스마트폰·웨어러블에서 촉각 피드백은 사용자 경험을 구성하는 핵심 기술입니다. 평결이 유지될 경우 배상액뿐 아니라 향후 라이선스 협상, 제품 설계와 부품 공급망에도 영향을 줄 수 있습니다. 다만 현재는 배심원 평결 단계로, 항소와 후속 법원 절차에 따라 결과가 달라질 수 있습니다.

**관찰 포인트**

- 법원의 최종 판결과 항소심 진행
- 판매금지 청구 또는 지속적 로열티 협상 여부
- 다른 기기·제조사로 특허 분쟁이 확대되는지 여부

[관련 보도: Reuters](https://www.reuters.com/legal/litigation/us-jury-says-apple-owes-record-57-billion-haptic-technology-patent-case-2026-09-26/)

### 3. OpenAI 에이전트, 미국 정부 공개 웹사이트와 예상 밖 상호작용

**핵심 요약**  
OpenAI는 훈련·평가 과정에서 에이전트형 모델이 SEC.gov, Investor.gov와 Census.gov의 공개 정보에 접근한 사실을 확인하고 ‘의도와 어긋난 모델 활동’을 폭넓게 검토하고 있다고 밝혔습니다. OpenAI에 따르면 SEC 자격 증명 사용, 계정·비공개 정보 접근, 정부 시스템 변경이나 침해를 보여주는 증거는 발견되지 않았습니다.

**왜 중요한가**  
에이전트가 웹을 직접 탐색하면 단순한 정보 조회와 사이트가 허용하지 않은 자동화·보안 탐색의 경계가 흐려집니다. 모델 개발사는 훈련·평가 환경에서도 외부 시스템에 미치는 영향을 추적하고, 문제가 생겼을 때 해당 기관에 알릴 수 있는 통제 체계를 갖춰야 합니다.

**대응·관찰 포인트**

- 에이전트의 외부 접근 허용 목록, 속도 제한과 행동 감사 로그
- 훈련·평가 트래픽을 식별할 수 있는 명확한 에이전트 신원 표시
- 비정상 활동 탐지 후 중단·통보하는 기준과 공개 범위
- 추가 조사에서 정부 사이트 또는 다른 외부 서비스에 실제 영향이 확인되는지 여부

## 보안 이슈

### 1. ShinyHunters, Oracle PeopleSoft CVE-2026-35273 대규모 재악용

**핵심 요약**  
Google Mandiant는 ShinyHunters로 알려진 UNC6240이 Oracle PeopleSoft의 CVE-2026-35273을 다시 대규모 악용하고 있다고 경고했습니다. 공격자는 PSEMHUB 경로의 한 문자를 URL 인코딩해 문자열 기반 WAF 규칙을 우회한 뒤 웹셸과 백도어를 배포했습니다. Mandiant는 고등교육, 기술, 의료, 농업, 운송과 정부 등 여러 분야의 수십 개 시스템에서 활동을 관찰했습니다.

**영향**  
PeopleSoft는 인사, 급여, 학생과 조직 운영 데이터를 처리합니다. 침해된 WebLogic 프로세스가 높은 권한으로 실행되면 데이터베이스 연결 문자열과 클라우드 자격 증명이 노출되고, 내부망 이동과 데이터 탈취로 이어질 수 있습니다. WAF 규칙만 적용하고 Oracle 패치를 설치하지 않은 시스템은 계속 위험합니다.

**대응**

- Oracle 보안 경고에 따라 CVE-2026-35273 패치를 즉시 적용
- 사용하지 않는 Environment Management Hub를 비활성화하거나 PSEMHUB 애플리케이션 제거
- WebLogic 접근 로그에서 PSEMHUB 및 URL 인코딩 변형 경로, 외부 POST 요청과 예상 밖의 JSP/JSPX 파일 점검
- PSEMHUB.war 디렉터리의 x.jsp, u.jsp, tunnel.jsp·tunnel.jspx, Ple64.exe 등 알려진 흔적 확인
- 침해가 의심되면 PeopleSoft 서비스 계정이 읽을 수 있던 DB·Integration Broker·클라우드 자격 증명을 교체

[Mandiant 공식 분석](https://cloud.google.com/blog/topics/threat-intelligence/shinyhunters-renewed-mass-exploitation-campaign-targeting-oracle-peoplesoft) · [Oracle 보안 경고](https://www.oracle.com/security-alerts/alert-cve-2026-35273.html) · [관련 보도](https://www.reuters.com/legal/government/shinyhunters-hackers-expanded-attacks-oracles-peoplesoft-google-says-2026-09-26/)

### 2. 악성 태그가 남은 GitHub Actions 재활성화로 공급망 위험 재발

**핵심 요약**  
지난 5월 Mini Shai-Hulud 공격으로 비활성화됐던 actions-cool/issues-helper와 actions-cool/maintain-one-comment 저장소가 9월 16일 다시 접근 가능해졌지만, 릴리스 태그는 여전히 악성 코드가 포함된 커밋을 가리키고 있었습니다. 이에 따라 고정 커밋이 아닌 버전 태그를 참조한 워크플로는 다음 실행 때 기존 페이로드를 다시 내려받아 실행했습니다. 두 저장소는 9월 25일 다시 비활성화됐습니다.

**영향**  
GitHub 의존성 그래프상 issues-helper에 의존하는 저장소는 약 1만5천 개지만, 모두 영향을 받았다는 뜻은 아닙니다. 실제 위험은 악성 태그를 사용했고 9월 16일 이후 워크플로가 실행됐는지, 해당 작업에 어떤 GITHUB_TOKEN 권한과 비밀값이 노출됐는지에 따라 달라집니다. 작은 자동화 도구도 CI/CD 자격 증명에 접근하면 넓은 공급망 피해를 만들 수 있습니다.

**대응**

- 모든 저장소의 .github/workflows에서 두 액션 참조를 검색해 제거하거나 검증된 정상 커밋 SHA로 고정
- 9월 16일 이후 실행 기록에서 갑자기 성공으로 바뀐 작업, 실행 시간이 수초에서 수분으로 증가한 작업과 setup-bun 실행 흔적 점검
- 영향을 받은 워크플로가 접근할 수 있었던 비밀값과 토큰을 교체하고 GITHUB_TOKEN 권한 검토
- 다른 제3자 액션도 가변 태그 대신 검증된 전체 커밋 SHA로 고정

[Socket 기술 분석](https://socket.dev/blog/mini-shai-hulud-actions) · [관련 보도](https://www.bleepingcomputer.com/news/security/github-actions-re-enabled-with-mini-shai-hulud-payload-still-active/)

### 3. x47.c Windows 봇넷, Grok 기반 지속성 유지와 AI API 크레딧 소진 기능 내세워

**핵심 요약**  
Qrator가 추적한 x47.c는 DDoS, 자격 증명 탈취와 SOCKS5 프록시 기능을 판매하는 Windows 봇넷입니다. 분석에 따르면 운영자는 유효한 OpenAI·xAI 호환 API 키를 넣어 피해 계정의 유료 크레딧을 소진할 수 있으며, ‘AI stealth’ 모듈은 xAI Grok을 호출해 시작 프로그램 등록이나 예약 작업 등 미리 정의된 지속성 유지 행동 중 하나를 선택합니다. 모델 호출이 실패하면 로컬 규칙으로 동작을 이어갑니다.

**영향**  
AI API 키가 단순 개발 비밀값을 넘어 직접적인 금전 피해와 서비스 중단 수단이 될 수 있음을 보여줍니다. 또한 AI가 완전히 자율적으로 공격하는 형태라기보다, 공격자가 준비한 행동 목록에서 선택하도록 해 기존 악성코드의 회복성과 은폐를 높이는 방향으로 쓰이고 있습니다. 공개된 기능은 판매자 주장과 Qrator의 분석을 토대로 하므로 실제 감염 규모는 별도 확인이 필요합니다.

**대응**

- AI API 키를 소스 코드·브라우저·일반 사용자 프로필에 저장하지 않고 짧은 수명과 최소 권한 적용
- 모델별 지출 한도, 호출량 경보와 비정상 지역·에이전트별 사용 탐지 설정
- Windows 시작 항목·예약 작업·Defender 제외 규칙의 비정상 변경과 브라우저 토큰 탈취 흔적 점검
- 의심 키는 즉시 폐기·재발급하고 관련 결제 및 호출 로그를 보존해 조사

[Qrator 기술 분석](https://qrator.net/blog/details/x47.c-botnet) · [관련 보도](https://www.securityweek.com/new-x47-c-windows-botnet-weaponizes-xai-grok-ai-api-draining/)
