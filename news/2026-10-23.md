## IT 이슈

### 1. Agent Skills 표준, Agentic AI Foundation으로 이관 발표

**공개일:** 2026-10-22(공식 발표일). 게시 시각 메타데이터는 자정 값이므로 정밀 공개 시각으로 사용하지 않았다. [공식 발표](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation)

**핵심 요약:** Anthropic이 Agent Skills 공개 표준을 Linux Foundation 산하 Agentic AI Foundation(AAIF)에 기부한다고 발표했다. 이관 대상은 명칭·로고, GitHub 조직과 도메인이다. 재단 가입 없이도 사용·기여를 계속할 수 있으며, 유지관리자는 개인 자격으로 참여한다. 버전별 릴리스, 공식 제안 절차, 작성·설치 보안 지침은 제안된 로드맵이다. [이관 범위·계획](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation)

**왜 중요한가 — 분석:** 에이전트용 작업 지식과 절차를 제품 간 재사용하는 형식의 거버넌스를 공동체로 넓히려는 변화다. 다만 재단 이관 자체가 개별 스킬의 품질·호환성·안전성을 인증하는 것은 아니다. [표준 설명](https://github.com/agentskills/agentskills)

**관찰 포인트 — 편집부 제안:** 기존 스킬을 즉시 바꾸기보다 향후 규격 버전과 제안 절차를 확인하자. 외부 스킬의 지시문·스크립트·참조 자료는 별도로 검토하고 필요한 권한만 부여하는 것이 좋다. [공식 규격 저장소](https://github.com/agentskills/agentskills)

### 2. Arc 브라우저, 12월 22일 데스크톱 종료 예고…데이터 이전 준비 필요

**공개 시점:** 공식 일정은 2026-10-22부터 시작한다. 독립 보도는 10월 23일 02:03 KST(10-22 17:03 UTC)에 게시됐다. [공식 공지](https://arc.net/), [보도 시각](https://www.theverge.com/tech/1016832/arc-browser-shutting-down)

**핵심 요약:** The Browser Company는 12월 22일 macOS·Windows용 Arc 사용을 종료하고 Arc 계정을 비활성화한다고 밝혔다. 10월 22일부터 신규 계정 생성이 중단됐으며, 11월 23일에는 iOS·Android의 AI 기능과 로그인·탭 동기화가 중단된다. 모바일 전체가 같은 날 종료되는 것은 아니며, iOS는 경량 브라우저 사용이 이어진다고 안내했다. [종료 일정](https://arc.net/)

**왜 중요한가 — 분석:** 브라우저에 저장한 업무 탭·계정·기록의 이전 일정이 생겼다. 회사는 계정 비활성화 후 관련 개인정보를 30일 내 삭제한다고 하므로, 종료 직전까지 이전을 미루지 않는 편이 좋다. [데이터 처리 안내](https://arc.net/)

**대응 — 편집부 제안:** 12월 22일 전에 탭·북마크 등 필요한 데이터를 내보내고 이전 결과를 확인하자. 공식 공지는 Dia 가져오기와 다른 브라우저용 링크 목록 내보내기를 안내한다. 내보낸 파일에 민감한 정보가 있는지도 확인해 보관해야 한다. [내보내기 FAQ](https://arc.net/)

## 보안 이슈

### 1. Railway, 기존 API 토큰 무효화…외부 서비스 키도 별도 교체 필요

**업데이트 시각:** 2026-10-22 13:17 KST(04:17 UTC). 최초 사고 공지는 조사 구간 밖이며, 이번 채택 근거는 구간 내 토큰 무효화와 후속 대응 지침 공개다. [공식 상태 기록](https://status.railway.com/incident/QH8L8B3E)

**핵심 요약:** Railway는 제3자가 암호화된 고객 환경변수와 일부 복호화된 내용에 접근했을 가능성을 밝혔다. 초기 분석에서는 일부 사용자로 범위가 제한될 수 있다고 설명하면서도, 모든 사용자에게 관련 자격증명 교체를 권고했다. 이후 기존 Railway API 토큰 전체를 무효화했다. [사고 배경](https://blog.railway.com/p/security-disclosure-wednesday-october-21st), [토큰 조치](https://status.railway.com/incident/QH8L8B3E)

**왜 중요한가 — 분석:** Railway 토큰을 재발급해도 환경변수에 저장한 외부 서비스의 API 키나 DB 자격증명이 자동으로 교체되지는 않는다. 발급 서비스별 대응이 필요하다. [대응 근거](https://blog.railway.com/p/security-disclosure-recommendation-check-for-anomalous-aws-access)

**대응:** 잠재적으로 노출된 키를 발급처에서 비활성화·교체하고 새 값으로 재배포하자. AWS 사용자는 CloudTrail과 청구 내역의 비정상 활동도 확인한다. [공식 지침](https://blog.railway.com/p/security-disclosure-recommendation-check-for-anomalous-aws-access)

**최신 상태·확인 수준:** 10월 23일 07:49 KST 공지에서는 전체 요금제의 빌드·배포가 대체로 정상 속도라고 밝혔다. 조치 발표는 공식 확인이지만 최종 피해 범위와 개별 키의 실제 악용 여부는 미확정이다. 전체 고객의 비밀정보 유출이나 현재 전체 배포 중단으로 단정하지 않는다. [상태·복구 범위](https://status.railway.com/incident/QH8L8B3E), [조사 범위](https://blog.railway.com/p/security-disclosure-wednesday-october-21st)
