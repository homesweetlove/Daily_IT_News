## IT 이슈

### 1. Cline 4.1.27, 모델에 전달되는 파일 읽기 결과의 추가 잘림 수정

**핵심 요약:** Cline은 11월 21일 4.1.27을 공개했다. 공식 릴리스 노트에 따르면 `read_files` 결과를 모델로 전달하는 과정에서 다시 8천 자로 잘라내던 처리를 수정했다. 이제 읽기 도구 자체의 제한인 **2천 줄 또는 약 4만 8천 자** 범위까지 결과를 전달한다. 무제한 파일 읽기를 제공한다는 의미는 아니다. [Cline 공식 릴리스](https://github.com/cline/cline/releases/tag/v4.1.27)

**왜 중요한가:** 파일을 읽은 도구의 출력과 모델이 실제 받는 내용 사이의 차이를 줄이는 변경이다. 같은 릴리스에는 인증을 요구하는 LM Studio 서버용 API 키 입력란, 서버가 읽기 전용으로 선언한 MCP 도구의 배지, 공급자 API 키·기본 URL 저장 후 모델 목록 갱신도 포함됐다. 배지는 서버의 선언을 표시하는 기능으로 설명돼 있다. [변경 내역](https://github.com/cline/cline/releases/tag/v4.1.27)

**관찰 포인트 — 편집부 제안:** 긴 파일의 중간 부분을 놓친 코드 검토가 있었다면 업데이트 후 해당 범위를 다시 읽어 확인하자. 읽기 전용 배지의 의미도 실제 실행 권한과 함께 검토하는 편이 좋다. 이는 발표된 수정 내용과 표시 방식에 근거한 사용 제안이다. [릴리스 원문](https://github.com/cline/cline/releases/tag/v4.1.27)

### 2. Signal, 모바일 AI 화면 접근 제한…앱과 운영체제 사이의 권한 문제가 쟁점

**핵심 요약:** The Hacker News는 11월 21일 Signal의 모바일 AI 접근 제한을 보도했다. 최초 공식 발표는 20일이다. Signal은 iOS 27과 AI 비서의 화면 읽기를 감지할 수 있는 Android 환경에서 스크린샷을 제한해 대화 내용의 수집을 막겠다고 설명했다. [21일 후속 보도](https://thehackernews.com/2026/11/signal-blocks-ai-agents-from-reading.html?m=0) · [Signal 공식 발표](https://signal.org/blog/protecting-your-privacy/)

**왜 중요한가:** Signal은 운영체제 AI가 화면에 표시된 내용을 수집하면 앱 외부의 저장·처리 경로로 전달될 수 있다고 지적했다. 동시에 스크린샷 제한은 불완전하며, 기기 파일시스템 등을 통한 다른 접근 가능성까지 해결하지 못한다고 밝혔다. macOS에는 같은 보호를 구현할 수 없다고 설명했다. 이는 암호화 프로토콜의 해독 문제가 아니라, 기기에서 표시·저장되는 정보에 대한 접근 통제 문제다. [Signal의 설명·보호 한계](https://signal.org/blog/protecting-your-privacy/)

**관찰 포인트:** Signal은 개발자가 화면·파일시스템·알림·API 등을 통한 AI 접근을 제외할 수 있는 수단과 명확한 기술 문서를 운영체제 업체에 요청했다. **편집부 제안:** 개인·조직의 AI 도입 검토에서도 연결된 앱 목록과 함께 운영체제 권한 및 앱별 보호 설정을 확인하자. [개발자 통제 수단 요청](https://signal.org/blog/protecting-your-privacy/)

## 보안 이슈

### 1. MONAI Label 취약점 악용 보도…수정 코드 병합과 패키지 배포는 별개

**핵심 요약:** The Hacker News는 11월 21일 Amazon Threat Intelligence의 조사와 MONAI Label의 경로 순회 취약점을 연결해 보도했다. MONAI Label 공식 권고는 **0.8.5 이하**에서 업로드한 이미지·라벨을 데이터 저장소 밖의 쓰기 가능한 경로에 기록할 수 있다고 설명한다. 기본 설정에서는 인증이 비활성화돼 있으며, 인증을 켜도 신뢰할 수 없는 사용자에게 ANNOTATOR 역할을 부여하면 위험이 남는다. [21일 보도](https://thehackernews.com/2026/11/attackers-ai-agents-found-zero-day-in.html?m=0) · [프로젝트 공식 권고](https://github.com/Project-MONAI/MONAILabel/security/advisories/GHSA-qc22-rmgc-vg94)

**왜 중요한가:** Amazon은 20일 공개한 조사에서 공격자의 공개 Cairn 관리 화면에 남은 기록을 분석했다고 밝혔다. 의료 영상 AI 애플리케이션에서 약 11분 만에 API 분석부터 임의 파일 쓰기에 도달했고, 이후 별도 세션에서 root 권한의 셸을 얻었다는 설명이다. **11분 만에 root를 획득했다는 의미는 아니다.** 중국 연계 행위자라는 평가는 중간 수준의 확신에 따른 것이며, 두 번째 대학망의 동일 취약점 악용은 추론으로 구분했다. [Amazon 원문 조사](https://aws.amazon.com/blogs/security/chinese-nexus-actors-cairn-ai-agents-found-a-zero-day-on-their-own/)

**적용 상태:** 공식 보안 권고는 수정 PR #1915를 안내하지만 수정 버전 항목에는 **None**을 표시하고, 다음 릴리스에 포함될 예정이라고 설명한다. PR은 10월 19일 병합됐다. 따라서 소스 코드가 수정됐다는 사실만으로 설치된 배포 패키지까지 안전하다고 판단할 수 없다. [공식 권고의 패치 상태](https://github.com/Project-MONAI/MONAILabel/security/advisories/GHSA-qc22-rmgc-vg94) · [수정 PR](https://github.com/Project-MONAI/MONAILabel/pull/1915)

**대응 포인트:** 공식 권고에 따라 인증을 켜고 신뢰할 수 없는 사용자에게 ANNOTATOR 역할을 주지 않으며, 비신뢰 네트워크에서 서버 접근을 차단하자. 서비스는 저장소 디렉터리에만 쓰기 권한이 있는 비특권 계정으로 실행한다. **편집부 제안:** 노출됐던 서버는 비정상 Python 시작 파일·실행 작업을 점검하고, 소스로 배포한다면 수정 코드 포함 여부를 별도로 확인하자. 임의 파일 쓰기의 영향은 서비스 계정의 권한에 따라 달라진다. [공식 완화 조치·영향](https://github.com/Project-MONAI/MONAILabel/security/advisories/GHSA-qc22-rmgc-vg94) · [관측된 공격 흐름](https://aws.amazon.com/blogs/security/chinese-nexus-actors-cairn-ai-agents-found-a-zero-day-on-their-own/)

### 2. N-central HF4 공개, Java 취약점 수정과 Agent·Probe 업데이트 안내

**핵심 요약:** N-able은 11월 21일 **N-central 2026.4 Hotfix 4**, 빌드 **2026.4.1.40**의 릴리스 노트를 공개했다. 이 버전은 내장 Java 패키지를 갱신해 **CVE-2026-114938**을 수정하며, 원격 제어·Intune 관련 문제를 해결하고 두 기능을 다시 활성화한다고 설명한다. [N-able 공식 릴리스 노트](https://status.n-able.com/2026/11/21/n-central-2026-4-hf4-release-notes/)

**왜 중요한가:** 공급업체는 호스팅형 NCOD 서버를 직접 업데이트하지만, 고객은 **호스팅형·자체 구축형 모두 Agent와 Probe를 업데이트해야 한다.** 자체 구축형 고객은 서버 업데이트도 직접 수행해야 한다. 서버만 갱신하고 관리 대상 구성요소를 남겨두는 방식으로 작업을 끝내지 않도록 범위를 확인해야 한다. [업데이트 책임·대상](https://status.n-able.com/2026/11/21/n-central-2026-4-hf4-release-notes/)

**대응 포인트:** 공식 문서의 최신 Agent·Probe 안내는 **2026.4.1.40**을 명시한다. 이전 버전은 지원되는 업그레이드 경로를 확인한 뒤 적용하자. **편집부 제안:** 서버·Agent·Probe별 적용 현황을 따로 확인하고 원격 제어·Intune 기능을 검증하자. [빌드·경로·Agent/Probe 안내](https://status.n-able.com/2026/11/21/n-central-2026-4-hf4-release-notes/)
