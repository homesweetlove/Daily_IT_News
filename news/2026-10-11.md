## IT 이슈

### 1. Bun 1.4.3, TypeScript 타입 검사까지 실행 도구에 통합

- **공개 시각:** 공식 GitHub API의 릴리스 게시 시각은 10월 10일 05:24:54 UTC, 한국시간 14:24:54다. 공식 블로그도 10월 10일자로 발표했다. [GitHub 릴리스](https://github.com/oven-sh/bun/releases/tag/bun-v1.4.3) · [공식 발표](https://bun.com/blog/bun-v1.4.3)
- **핵심 요약:** 새 `bun check`는 `tsconfig.json`을 읽어 타입 오류를 검사한다. 실행·빌드·테스트 전 검사하는 `--check`도 추가됐다. `Bun.FetchSession`은 요청 그룹별 TLS·프록시·연결 풀 설정을 분리한다. [공식 릴리스 발표](https://bun.com/blog/bun-v1.4.3)
- **왜 중요한가:** 타입 검사와 실행 작업을 같은 도구로 연결할 수 있다. 다만 `bun check`는 JavaScript나 `.d.ts`를 생성하지 않으므로, 타입 선언 파일을 배포하는 프로젝트에서는 기존 생성 단계를 유지해야 한다. [공식 타입 검사 문서](https://bun.com/docs/runtime/check)
- **관찰 포인트:** 도입 전 기존 검사 결과와 비교하자. `package.json`에 `check` 스크립트가 있으면 `bun check`가 그 스크립트를 실행하므로, 내장 검사를 직접 호출하려면 `bun --check`를 사용한다. 회사의 성능 수치는 이번 리포트의 판단 근거에서 제외했다. [공식 타입 검사 문서](https://bun.com/docs/runtime/check)

- **핵심 요약:** 나델라는 AI 모델의 지능과 실제 행동 권한을 분리하고, 접근 통제와 안전장치를 모델 바깥에 두자고 제안했다. 주요 행동의 변조 방지 기록, 독립 검증, 권한 있는 사람이 작업 도중 모델을 멈출 수 있는 장치도 강조했다. [나델라 원문](https://snscratchpad.com/posts/models-as-insider-risks/)
- **왜 중요한가 — 편집부 해석:** 업무용 AI를 도입할 때 모델의 답변 품질뿐 아니라 실행 권한·기록·중단 절차를 함께 평가해야 한다는 관점이다.
- **관찰 포인트:** 이 글은 설계 원칙에 관한 제안이다. Microsoft의 새 제품 출시나 확정된 의무 정책으로 해석해서는 안 된다. [나델라 원문](https://snscratchpad.com/posts/models-as-insider-risks/)

### 1. 한국 금융권 침해에 ARTEX·Claude Code 활용 흔적 — 기존 사건의 새 보도

- **새 보도일:** BleepingComputer 원문은 10월 10일 10:16 AM으로 표기한다. 기사 수집 피드의 14:16 UTC와 대조하면 한국시간 23:16이다(시간대 환산은 피드로 보조 확인). [시각 대조](https://www.scifintel.com/) 사건의 활동 기간은 9월 말~10월 초, CrowdStrike 원 연구 공개일은 10월 7일이다. 오늘 새로 발생한 공격을 뜻하지 않는다. [새 보도](https://www.bleepingcomputer.com/news/security/hacker-used-artex-ai-and-claude-agents-to-target-south-korean-banks/) · [원 연구](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/)
- **핵심 요약:** CrowdStrike는 한국 금융기관을 겨냥해 데이터가 반출된 활동과 관련된 공격 인프라를 분석했다. 열린 디렉터리에서 ARTEX 설정, Claude Code 세션 기록, 메모리 파일을 확보해 AI 도구 사용 흔적을 확인했다. [원 연구](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/)
- **왜 중요한가:** 연구팀은 AI 도구가 짧은 기간 여러 침입을 수행하는 데 활용됐다고 평가했다. 다만 완전 자율 공격이 입증된 것은 아니며, 피해기관 전체 수와 공격자 신원은 확정되지 않았다. 중국어 사용자·금전 목적이라는 평가는 중간 신뢰도이며, 국가 배후를 단정할 수 없다. [원 연구](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/)
- **대응 — 편집부 권고:** 원 연구의 침해지표(IOC)를 대외서비스·협력사 접속·데이터 반출 로그와 대조하자. 공유 프록시 IP 일치만으로 침해를 확정하지 말고 추가 증거를 확인해야 한다. 이 보고서에는 대응할 단일 CVE나 제품 패치 버전이 제시되지 않았다. [IOC와 분석 원문](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/)

### 2. 산업기업 내부자 파괴·갈취 사건 후속 보도 — 관리자 권한 집중의 위험

- **새 보도일:** SecurityWeek 10월 10일 07:00 AM ET, 한국시간 20:00. 공격은 2023년 11월 25일, 선고는 2026년 9월 28일이며 법무부 발표는 10월 5일이다. 이번 항목은 과거 사건의 후속 보도다. [새 보도](https://www.securityweek.com/insider-cyber-extortion-plot-against-industrial-firm-lands-engineer-in-prison/) · [미 법무부 발표](https://www.justice.gov/usao-nj/pr/former-employee-industrial-company-sentenced-32-months-prison-computer-attack-and)
- **핵심 요약:** 내부 인프라 엔지니어가 예약 작업으로 회사 계정 삭제와 비밀번호 변경을 실행해 접근을 막고, 20비트코인을 요구했다. 컴퓨터 공격·갈취 사건으로 징역 32개월을 선고받았다. [미 법무부 발표](https://www.justice.gov/usao-nj/pr/former-employee-industrial-company-sentenced-32-months-prison-computer-attack-and)
- **왜 중요한가 — 편집부 해석:** 외부 취약점 악용이 없어도 특권 계정과 예약 작업 권한을 가진 내부자가 운영 접근을 광범위하게 파괴할 수 있다는 사례다.
- **대응 — 편집부 권고:** 관리자 계정 대량 삭제, 비밀번호 일괄 변경, 도메인 컨트롤러 예약 작업을 경보 대상으로 삼자. 특권 접근 승인과 백업 관리 권한을 분리하고 독립적인 복구 경로를 시험해야 한다. 협박 메일의 “모든 백업 삭제” 주장은 확인된 피해와 구분한다. 특정 제품 CVE의 패치로 해결되는 사건은 아니다. [협박 내용과 사건 보도](https://www.securityweek.com/insider-cyber-extortion-plot-against-industrial-firm-lands-engineer-in-prison/)
