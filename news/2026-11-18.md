### 1. Microsoft, 로컬 AI·개발 환경 확대…정식 제공과 미리보기 구분 필요

**핵심 요약:** Microsoft는 **17일 Ignite 발표**에서 Azure Local 기반 **Foundry Local, GitHub Enterprise Local, AMD SEV-SNP 기밀 VM**의 정식 제공을 알렸다. Foundry Local은 연결·단절 환경에서 로컬 추론을 지원한다. GitHub Enterprise Local은 GitHub Enterprise Server를 사전 구성한 가상 어플라이언스로 제공해 저장소·CI/CD·개발 산출물을 조직 인프라에 둘 수 있게 한다. [Microsoft 공식 발표](https://techcommunity.microsoft.com/blog/azurearcblog/whats-new-with-sovereign-private-cloud-at-microsoft-ignite-2026/4573886)

**왜 중요한가:** 데이터와 코드를 조직이 통제하는 환경에서 처리하려는 수요에 대응하는 변화다. 다만 에이전트 서비스·가드레일, 연결 상태에서 단절 상태로의 전환, Intel TDX 기밀 VM, 로컬 DocumentDB·Blob Storage는 **미리보기**다. 제품군 전체가 동일한 지원 단계라고 보면 도입 범위를 잘못 판단할 수 있다. [제공 단계의 근거](https://techcommunity.microsoft.com/blog/azurearcblog/whats-new-with-sovereign-private-cloud-at-microsoft-ignite-2026/4573886)

**관찰 포인트 — 편집부 제안:** 필요한 기능의 제공 단계와 지원 하드웨어를 먼저 확인하고, 단절 환경의 모델·패키지 갱신 및 복구 절차를 시험할 필요가 있다. 공식 발표는 연결 환경의 GitHub Copilot 활용과, 단절 환경에서 Foundry Local 모델을 활용하는 AI 개발을 구분한다. 두 환경의 사용 경험과 운영 조건을 각각 검증하는 편이 좋다. [공식 발표](https://techcommunity.microsoft.com/blog/azurearcblog/whats-new-with-sovereign-private-cloud-at-microsoft-ignite-2026/4573886)

### 2. AWS, 코딩 에이전트에서 계정 생성과 배포를 연결

**핵심 요약:** AWS는 **17일** Claude Code·Codex·Cursor 같은 코딩 에이전트 환경에서 신규 AWS 가입 경험을 여는 기능을 발표했다. 브라우저에서 가입을 마치면 단기 자격 증명을 에이전트 환경으로 반환해 배포를 이어갈 수 있다. 첫 프로젝트에는 기본 리전과 IAM 역할 관리 기능, 자동 갱신되는 단기 자격 증명이 준비된다고 설명했다. 이용 경로는 AWS 플러그인 또는 Agent Toolkit 설정이다. [AWS 공식 발표](https://aws.amazon.com/about-aws/whats-new/2026/11/agentic-account-creation/)

**왜 중요한가:** 가입·자격 증명 설정을 위해 개발 흐름을 오가는 단계를 줄인다. 발표가 설명하는 것은 브라우저 가입과 자격 증명 전달의 연결이며, 신원 확인이나 비용·권한 결정을 사람이 검토할 필요가 사라진다는 의미로 해석해서는 안 된다. [발표된 기능 범위](https://aws.amazon.com/about-aws/whats-new/2026/11/agentic-account-creation/)

**관찰 포인트 — 편집부 제안:** 첫 배포 전에 선택 리전, 에이전트에 부여할 IAM 역할, 생성할 리소스와 예상 비용을 검토할 것을 제안한다. 단기 자격 증명 사용과 별개로 배포 권한·사용량 통제는 실제 프로젝트 요구에 맞춰 확인해야 한다. [구성 방식의 근거](https://aws.amazon.com/about-aws/whats-new/2026/11/agentic-account-creation/)

## 보안 이슈

### 1. Tails 7.17.1 긴급 배포, uBlock Origin 범용 XSS에 대응

**핵심 요약:** Tails는 **17일 7.17.1**을 긴급 배포하면서 Tor Browser에 포함된 **uBlock Origin을 임시 제거**했다. 한 번의 클릭으로 악성 사이트가 이후 방문하는 다른 사이트에 임의 JavaScript를 삽입할 수 있는 범용 XSS에 대한 대응이다. 개발진은 데이터 탈취·변조 가능성을 설명했으며, 공지 시점에 실제 악용 사례는 알지 못한다고 밝혔다. [Tor Project 공식 릴리스](https://blog.torproject.org/new-release-tails-7_17_1/)

**영향:** Tor Browser의 **Standard와 Safer는 영향**을 받고 **Safest는 영향받지 않는다.** Tails를 다시 시작하면 이 결함으로 삽입된 악성 uBlock Origin 설정이 삭제된다. 개발진은 확장을 가능한 한 빨리 다시 포함할 계획이다. [공식 영향 설명](https://blog.torproject.org/new-release-tails-7_17_1/)

**대응:** 7.17.1로 업그레이드한다. Tails 7.0 이상에서는 Persistent Storage를 유지하는 자동 업그레이드가 가능하며, 실패하면 공식 수동 업그레이드 안내를 따른다. 기존 USB에 **업그레이드 대신 새로 설치하면 Persistent Storage가 지워지므로** 작업 경로를 확인해야 한다. 편집부는 재시작으로 설정을 지우는 조치와 보안 업데이트 적용을 함께 수행할 것을 제안한다. [공식 업그레이드 지침](https://blog.torproject.org/new-release-tails-7_17_1/)

### 2. 후가쿠 침입 후속 보도…저장된 SSH 키의 외부 서비스 악용 위험

**새 소식:** 17일 후속 보도는 RIKEN의 **16일 공식 공지**를 다뤘다. RIKEN은 10~13일 공개 운영 현황 대시보드를 발판으로 내부 운영망에 침입이 있었고 일부 서버에 악성 프로그램이 설치됐다고 밝혔다. 구체적인 침입 방법은 조사 중이다. 후가쿠 운영은 **14일 04:30 일본시간**에 중단됐다. [RIKEN 공식 공지](https://www.riken.jp/pr/news/2026/20261116_2/index.html), [17일 시사통신 보도](https://jen.jiji.com/japan/society/2026111700573/)

**영향:** 유출됐거나 유출됐을 가능성이 있는 정보는 후가쿠 이용자 최대 4,222명, 리큐 이용자 최대 375명의 등록 정보와 홈 디렉터리의 연구 파일·SSH 개인키·접근 키 등이다. **연구 성과 유출을 보여주는 구체적 사실은 확인되지 않았다.** 일부 인증정보로 다른 시스템에 접속하려 한 사실은 확인됐으며 2차 피해는 조사 중이다. [RIKEN 공식 공지](https://www.riken.jp/pr/news/2026/20261116_2/index.html)

**왜 중요한가·대응:** 한 연구 인프라에 저장한 키가 다른 기관·서비스의 접근 수단이 될 수 있다. RIKEN은 이용자 로그인 공개키를 무효화했고, 이용자가 후가쿠에 저장했던 키·인증정보는 **각 접속 대상 서비스에서 폐기하고 재발급**하도록 요청했다. 편집부는 해당 서비스의 접속 기록과 권한 변경도 함께 점검할 것을 제안한다. [RIKEN의 이용자 조치 요청](https://www.riken.jp/pr/news/2026/20261116_2/index.html)

### 3. Kokoro 계정 장악 연구, 모델 가중치도 공급망 검증 대상

**새 소식:** 17일 보도에 따르면 Alon Hertz 연구진은 Kokoro 음성 합성 모델 게시자의 Hugging Face 계정을 장악한 과정을 공개했다. 연구진은 게시자가 사용하던 도메인을 등록한 뒤 비밀번호 재설정으로 계정에 접근했다고 설명한다. 이는 **연구진의 공개 설명**이며, 보도 당시 Hugging Face의 답변은 없었다. [연구진 원문](https://medium.com/@alonhertz1/one-click-from-180-million-downloads-taking-over-the-hugging-face-account-behind-an-ai-model-ac61c16305b7), [17일 보도](https://www.bleepingcomputer.com/news/security/researchers-hijack-hugging-face-account-for-popular-kokoro-ai-model/)

**핵심 요약·확인 범위:** 연구진은 추론 코드를 바꾸지 않고 가중치를 수정해 입력 텍스트와 다른 말을 출력하는 실험을 로컬에서 수행했다고 밝혔다. **변조 가중치는 Hugging Face에 업로드하지 않았다고 명시했다.** 이번 공개 내용을 악성 모델의 실제 대규모 배포나 이용 기업의 침해 확인으로 확대해서는 안 된다. [실험·미배포 설명](https://medium.com/@alonhertz1/one-click-from-180-million-downloads-taking-over-the-hugging-face-account-behind-an-ai-model-ac61c16305b7)

**왜 중요한가:** 익숙한 게시자 이름과 정상적인 파일 형식만으로 새 가중치의 동작까지 신뢰하기 어렵다는 사례다. **관찰 포인트 — 편집부 제안:** 자동으로 최신 모델을 가져오는 경로를 점검하고, 승인된 커밋·파일 해시 고정과 업데이트 전 동작 회귀 검증을 함께 적용할 것을 제안한다. 게시자 계정의 복구 이메일·도메인 소유권 관리도 검토할 필요가 있다. [문제 제기의 근거: 연구진 원문](https://medium.com/@alonhertz1/one-click-from-180-million-downloads-taking-over-the-hugging-face-account-behind-an-ai-model-ac61c16305b7)
