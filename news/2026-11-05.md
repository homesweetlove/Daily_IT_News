## IT 이슈

### 1. Conductor, Meta 합류 발표…Cloud 이용자는 11월 20일 전 데이터 이전 필요

**새 소식:** Conductor는 11월 4일 Meta 합류를 공식 발표하고 기존 서비스의 전환 일정을 공개했습니다. 같은 날부터 신규 가입과 앱 다운로드를 중단하며, 기존 Pro 이용자에게는 Pro 기능을 무료로 제공한다고 설명했습니다. [Conductor 공식 공지][1]

**핵심 일정:** 공지 기준 **11월 13일** Conductor Cloud 작업 공간이 읽기 전용으로 바뀌어 새 메시지를 보낼 수 없게 됩니다. **11월 20일** Cloud를 종료하고 사용자 데이터 삭제를 시작합니다. 로컬 Conductor는 **2027년 초까지** 새 모델 지원과 중요한 버그 수정을 이어갈 계획입니다. [Conductor 공식 공지][1]

**영향과 대응:** Cloud 작업 공간을 우클릭해 `Transfer to local`을 선택하면 작업 공간과 대화를 Mac으로 옮길 수 있습니다. 전체 데이터는 `Settings → Account → Export data`에서 내보내도록 안내합니다. 날짜는 회사 공지의 표기를 따르며, 사용자는 종료일 전에 이전을 마쳐야 합니다. **편집부 분석:** 개발 기록과 진행 중인 작업을 보존할 수 있도록, 내보낸 자료가 실제로 열리는지까지 확인하는 것이 좋습니다. [공식 이전·내보내기 안내][1]

### 2. Tencent Hy4 출시…시각 이해·컴퓨터 조작 확대, 가중치 공개는 후속 계획

**새 소식:** Tencent는 11월 4일 Hy4 출시를 발표했습니다. 회사 설명에 따르면 새 모델은 시각 이해 기능을 도입하고, 명령줄과 그래픽 인터페이스를 조작하는 컴퓨터 사용 기능을 지원합니다. [Tencent 공식 배포문][2]

**핵심 내용:** Hy4는 Tencent Cloud TokenHub, WorkBuddy, CodeBuddy 등에서 제공되며, OpenRouter 등 외부 플랫폼을 통한 API 제공도 안내했습니다. 한편 **모델 가중치와 시스템 카드는 앞으로 수일 내 공개할 계획**이라고 밝혔습니다. 따라서 이번 서비스 출시 발표만으로 다운로드 가능한 정식 가중치나 배포 라이선스까지 확인됐다고 볼 수는 없습니다. [Tencent 공식 배포문][2]

**왜 중요한가 / 관찰 포인트 — 편집부 분석:** 문서·이미지 이해에서 실제 소프트웨어 조작으로 활용 범위가 넓어지는 흐름입니다. 도입 시에는 API의 기능과 권한 통제, 실제 작업 성공률을 평가하고, 자체 호스팅을 검토한다면 후속 가중치·시스템 카드·라이선스를 확인해야 합니다. 회사가 제시한 성능 우위 주장을 독립 검증 결과로 취급하지 않았습니다.

## 보안 이슈

### 1. APT 패키지 검증 우회, root 권한 코드 실행 위험…배포판별 수정본 확인

**새 소식:** Debian과 Ubuntu는 11월 4일 **CVE-2026-109518** 수정 내용을 공개했습니다. Debian 권고는 HTTP 리디렉션 이후 다운로드를 재개하는 과정의 파일 처리 문제로, 검증한 패키지가 다른 내용으로 대체돼 root 권한 코드 실행으로 이어질 수 있다고 설명했습니다. [Debian DSA-6607-1][3], [Ubuntu USN-8996-1][5]

**영향 조건:** 공격자는 악성 미러·프록시 등을 통해 APT와 저장소 사이의 HTTP 트래픽을 조작할 수 있어야 하며, 다운로드 재시도 설정 `Acquire::Retries`가 0이 아니어야 합니다. 이 설정은 Debian 12와 Ubuntu 22.04부터 기본으로 활성화됩니다. 더 오래된 릴리스도 별도 스크립트나 설정으로 재시도를 켰다면 확인이 필요합니다. [Ubuntu CVE 기록][4], [APT 개발팀 공지][6]

**대응:** 공식 권고에서 확인한 대표 수정 패키지는 다음과 같습니다. 배포판과 릴리스에 맞는 보안 저장소에서 갱신해야 합니다. [Debian 권고][3], [Ubuntu 수정 패키지 표][5]

| 배포판·릴리스 | 수정된 apt 버전 |
|---|---|
| Debian stable (trixie) | 3.0.4 |
| Ubuntu 26.10 | 3.3.3ubuntu0.1 |
| Ubuntu 26.04 LTS | 3.2.1ubuntu0.1 |
| Ubuntu 24.04 LTS | 2.8.4ubuntu0.1 |
| Ubuntu 22.04 LTS | 2.4.15ubuntu0.1 |

Ubuntu 20.04 이하의 일부 릴리스는 Ubuntu Pro 또는 Legacy Support 경로의 수정본을 안내합니다. **편집부 분석:** 서버뿐 아니라 CI 이미지와 내부 패키지 미러를 사용하는 환경에서도 실제 apt 버전과 재시도 설정을 점검할 필요가 있습니다. 다운로드 서명 검증이 있다는 이유만으로 이번 파일 교체 경로까지 보호된다고 가정해서는 안 됩니다. [Ubuntu 릴리스별 지원 상태][4]

### 2. Rails Active Storage 파일 쓰기·읽기 결함 수정…업로드 분석 단계도 점검 대상

**새 소식:** Rails는 11월 4일 **GHSA-f3w6-w445-fwh9** 권고를 공개하고 Active Storage **8.1.4.1·8.0.5.2**에서 문제를 수정했습니다. 권고 기준으로 CVE 번호는 아직 부여되지 않았습니다. [Rails 공식 권고][7]

**영향:** ImageMagick으로 Active Storage 첨부 파일을 처리하고, 관련 포맷 처리기를 차단하지 않은 보안 정책 아래에서 신뢰하지 않는 사용자의 업로드를 허용하는 앱이 대상입니다. 공격자는 서버에 임의 파일을 쓸 수 있고, **Disk 서비스에 첨부 파일을 저장하는 경우** 앱 프로세스가 읽을 수 있는 파일에도 접근할 수 있습니다. 첨부 단계의 분석만으로 경로가 실행되므로 이미지 변환이나 미리보기를 만들지 않는 앱도 확인해야 합니다. [Rails 공식 권고][7]

**대응:** 해당 계열의 수정 버전으로 올리고, `:mini_magick`을 쓰는 앱은 **mini_magick 5.1 이상**을 함께 사용해야 합니다. 영향 조건에 해당하며 Disk 서비스를 사용하는 앱에는 `secret_key_base`와 앱이 읽을 수 있는 다른 비밀 값의 교체도 권고합니다. [Rails 공식 권고][7]

**왜 중요한가 / 관찰 포인트:** Rails 가이드는 MiniMagick을 통해 실제 로드된 ImageMagick 정책을 확인하도록 안내합니다. 앱이 부팅 후 실행 환경을 덮어쓰거나 사용자 정의 실행 셸을 쓰면 기본 정책이 적용되지 않을 수 있습니다. **편집부 분석:** 패키지 버전 확인에 더해 실행 중인 앱의 정책과 업로드 처리 경로까지 확인해야 업데이트의 효과를 판단할 수 있습니다. [Rails 공식 가이드: ImageMagick Security Policy][8]
