### 1. Microsoft 365 장애, 공지 상태는 복구로 전환…잔여 영향 확인은 계속

**새 소식:** Microsoft 장애 번호 **MO1550821**의 14일 공지에서 상태가 `serviceRestored`로 표시됐다. 펜실베이니아대가 공개한 Microsoft 관리자 콘솔 공지 사본 기준으로, 최종 설명은 14일 04:17 UTC에 게시됐고 기록의 마지막 갱신 시각은 같은 날 14:24 UTC다. 전날의 서비스 저하 상황에서 달라진 후속 내용이다. [Microsoft 공지 공개 사본](https://mailservices.isc.upenn.edu/computing/email/penno365/alerts/ms-incidents.html)

**핵심 요약:** Microsoft는 앞선 네트워크 용량 증설 과정의 문제가 최근 네트워크 변경 이후 드러났다고 설명했다. 근본 문제를 처리했으며 안정성을 확인하면서 서비스를 단계적으로 복구했다고 밝혔다. 사이버 공격이나 AI·에이전트와 관련된 문제가 아니라는 설명도 덧붙였다. Exchange Online과 이메일에 의존하는 기능이 영향을 받았으며, 전체 사후 분석 보고서는 검토 후 제공할 예정이다. [Microsoft 공지 공개 사본](https://mailservices.isc.upenn.edu/computing/email/penno365/alerts/ms-incidents.html)

**왜 중요한가:** 복구 상태 표시와 별개로 같은 최종 설명에는 남은 고객·지역의 서비스 복원을 계속한다는 문구가 있다. 모든 조직의 모든 기능이 동시에 정상화됐다고 단정하기 어렵다. **관찰 포인트:** 관리자는 메일 송수신과 지연 메일, 이메일 연동 업무 자동화를 실제로 시험하고, 재처리할 작업을 확인할 것을 제안한다. 상세 원인과 재발 방지책은 사후 분석 보고서로 확인할 필요가 있다. [Microsoft 공지 공개 사본](https://mailservices.isc.upenn.edu/computing/email/penno365/alerts/ms-incidents.html)

### 2. DeepSeek, 검색·문서·음성을 개발자 API로 확대

**새 소식:** 14일 후속 보도는 DeepSeek이 **13일 공식 변경 기록**에서 공개한 애플리케이션 API를 다뤘다. 공식 문서는 `deepseek-flash`에서 Messages·Responses·Chat Completions 형식으로 웹 검색, 파일 입력, URL 읽기 기능을 이용할 수 있다고 명시했다. [공식 변경 기록](https://api-docs.deepseek.com/updates/), [14일 보도](https://neuralbrew.ai/en/articles/2026/11/deepseek-api-app-features-web-search-voice/)

**핵심 요약:** 웹 검색은 인용을 포함한 답변을 지원하며, 추론 기능을 켜면 여러 단계에 걸쳐 검색하고 링크를 읽는다. PDF·Office 문서·이미지는 텍스트 추출 또는 문서 구조 분석을 거쳐 대화 문맥에 들어간다. 검색·페이지 가져오기, OCR, 음성 인식과 음성 합성은 독립 API로도 제공된다. 도구 호출과 문맥 조립은 서비스 측에서 처리한다. [공식 변경 기록](https://api-docs.deepseek.com/updates/)

**왜 중요한가:** 개발자가 검색·문서 처리·음성 기능을 조합하는 작업을 줄일 수 있다는 의미가 있다. **관찰 포인트:** 도입 전에는 실제 한국어 문서에서 인용 정확도와 표·레이아웃 추출 품질, 응답 지연, 사용량별 비용을 시험할 것을 제안한다. 자료를 외부 API로 전송하는 범위도 함께 검토해야 한다. 이는 기능 공개에 대한 편집부의 도입 검토 항목이며, 성능 개선이 검증됐다는 뜻은 아니다. [기능 범위의 근거: 공식 변경 기록](https://api-docs.deepseek.com/updates/)

### 1. UnrealIRCd 명령 주입 결함 실제 악용…연결된 서버 전체를 점검해야

**새 소식:** 14일 보도에 따르면 CISA는 **13일 CVE-2026-114713을 알려진 악용 취약점 목록(KEV)에 추가**했다. 공식 목록의 대응 기한은 16일이며 포렌식 분류·점검 필요 표시도 있다. 이 기한은 해당 미국 연방기관 지침의 적용 맥락에서 이해해야 한다. [CISA 공식 KEV 데이터](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json), [14일 보도](https://securityaffairs.com/203040/hacking/u-s-cisa-adds-check-point-and-unrealircd-flaws-to-its-known-exploited-vulnerabilities-catalog.html)

**핵심 요약:** 두 대 이상이 연결된 UnrealIRCd 네트워크에서 일반 사용자가 서버 간 명령을 주입해 **IRC 서버 권한으로 실행**시킬 수 있는 결함이다. 유지관리자는 사용자 강제 종료나 네트워크 차단 등 IRC 관리 명령의 악용을 설명했다. 운영체제의 셸 명령 실행이나 루트 권한 획득이 확인됐다는 의미로 확대해서는 안 된다. [CISA 공식 KEV 데이터](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json), [유지관리자 공지](https://forums.unrealircd.org/viewtopic.php?t=9487)

**왜 중요한가:** 연결된 IRC 네트워크의 신뢰를 악용하므로 서버 한 대만 확인하고 대응을 끝내기 어렵다. **대응:** 7일 공개된 **6.2.7.1로 업그레이드**하거나, 대상 6.0.0~6.2.7 서버에 공식 `bundle-20261107` 핫패치를 적용하고 모듈 상태를 확인한다. Windows 환경이나 핫패치 적용에 실패한 환경은 업그레이드해야 한다. 임시 필터 우회책은 모든 서버가 6.0.4 이상이어야 하는 조건이 있으므로 적용 조건을 먼저 확인한다. 연결된 서버 전체의 패치 여부와 의심스러운 IRC 관리 동작을 점검할 것을 제안한다. [유지관리자 공지](https://forums.unrealircd.org/viewtopic.php?t=9487)

### 2. ScreenConnect SCKit 공격 후속 분석…클라이언트 패치와 확장 기능 차단 병행

**새 소식:** 14일 후속 보도는 Microsoft가 13일 공개한 **SCKit** 분석을 다뤘다. Microsoft는 MSP의 ScreenConnect 환경을 악용해 고객 단말에 무단 원격접속 클라이언트와 SCKit을 배포한 활동을 확인했다. 기술자 세션으로 확산하려는 기능도 분석했지만, 그 경로가 모든 관측 사례에서 성공했다고 확인한 것은 아니다. 최초 침입 경로와 확장 기능의 역할은 조사 중이다. [Microsoft 분석](https://www.microsoft.com/en-us/security/blog/2026/11/13/sckit-abuses-screenconnect-deploy-remote-access-target-technician-sessions/), [14일 후속 보도](https://root2sec.com/threat-intel/sckit-abuses-screenconnect-to-deploy-remote-access-and-target-technician-sessions/)

**핵심 요약·영향:** ConnectWise의 13일 21:15 UTC 권고는 **모든 기술자 클라이언트를 26.6.5 이상으로 갱신**하도록 요구한다. 이 클라이언트 수정은 CVE-2026-84869와 관련된다. 별도로 자체 구축 환경에서는 **Labtech Plus, RMM Plus, RMM+, RMM Plus Password Link, RMM+ Password Link** 확장을 비활성화해야 한다. ITBoost Integration·RepairShopr Integration·Guest Session Starter도 예방 차원의 비활성화 대상에 포함됐다. 공급사가 고객의 자체 구축 서버에서 대신 끌 수 없으므로 관리자가 조치해야 한다. [ConnectWise 공식 권고](https://www.connectwise.com/company/trust/advisories)

**대응:** 클라우드 콘솔이나 서버의 갱신 여부와 별개로 기술자 PC의 실제 클라이언트 버전을 확인하고, 해당 확장은 추가 안내 전까지 비활성 상태로 유지한다. 침해가 의심되면 무단 원격접속 프로그램뿐 아니라 예약 작업 등 지속성, 계정·웹 세션 노출도 조사해야 한다. 확장 기능을 끄는 작업만으로 기존 침해가 정리되지는 않는다. [ConnectWise 공식 권고](https://www.connectwise.com/company/trust/advisories), [Microsoft 분석](https://www.microsoft.com/en-us/security/blog/2026/11/13/sckit-abuses-screenconnect-deploy-remote-access-target-technician-sessions/)

**관측의 범위:** Huntress가 별도로 조사한 암호화폐 거래소 이름의 가짜 게스트 세션에서는 악성 파일 전송·명령 실행 또는 기술자 대상 페이로드 전달 증거가 발견되지 않았다. 이 세션 집단과 SCKit의 연관성도 확인되지 않았다. 낯선 세션에는 접속하지 말고, 삭제 전에 세션 데이터와 로그를 보존하라는 권고를 참고할 수 있다. 무단 세션 발견, 고객 단말 침해, 기술자 단말로의 확산 성공은 구분해 판단해야 한다. [Huntress 조사](https://www.huntress.com/blog/fake-crypto-exchange-sessions-screenconnect)
